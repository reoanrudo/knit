# Tsunagu 商品化方針・品質基準

2026-09-27 更新。製品の対象は [製品定義](product-definition.md) に従う。以下の実装状況は主に既存のMac/Windows版の監査時点の記録であり、他OS対応の完了を意味しない。

## 目指す体験

メーカーやOSの異なる複数のPCを、ひとつの作業環境として使える、世界向けの製品をつくる。タブレットも完成形の構想に含める。

MacとWindowsの2台限定、日本市場限定、MVPを完成物とする従来の前提は取り下げる。操作・データ・作業の引き継ぎを共通化し、OSが提供する機能と権限の違いに対応する。

製品として、初回導入、毎日の操作、復旧、更新、サポートまで完成条件に含める。市場順位と競合優位性は未検証。

## 現状と販売前の障害

| 項目 | 現在の根拠 | 商品化に必要な変更 |
|---|---|---|
| 初回接続 | 自動検出・6桁コード登録・OS保護保存を実装 | 初見ユーザーによる新規環境での通し試験を完了する |
| 通信 | commonにNoise暗号化・相互認証・専用転送経路の実装あり | 誤った相手・失効・再登録・不正データを含めて独立したレビューと検証を行う |
| 配布 | 従来は開発者のenvを自動同梱し、ビルド失敗を見逃し得た | 今回、非同梱・失敗時停止・マニフェスト・ハッシュ・ZIP検査を実装 |
| Windowsの表示 | docs/agent-guide.mdにDPI非対応の記載 | 100/125/150/200%で文字・アイコン・配置・入力座標を検証する。倍率を跨ぐ画面移動にも対応する |
| 入力 | 日本語キーやスクロールの実装あり。一部E2Eは手動検証領域 | JIS/US、IME、修飾キー、長押し、スリープ復帰を実機で確認する |
| ファイル | 双方向コピー・専用転送経路あり。Win→Macの掴みドラッグは未完成と記載 | 未完成の操作を広告に含めず、転送の進捗・取消・失敗・再試行・内容一致を保証する |
| 配布後の運用 | アドホック署名、bat中心の導入、開発専用デプロイ | 署名された導入・更新、失敗時の旧版復帰、アンインストールと設定保持の選択を用意する |

これはソース・資料の監査であり、全機能の実機検証結果ではない。並行開発があるため、検証時はリリースのマニフェストと対象機器を固定する。

## 製品全体の範囲

複数台・同一OS同士・異なるOS同士を扱い、PCとタブレットが参加できる共通基盤を設計する。入力、データ、作業コンテキスト、ワークスペースの各領域を製品の構想に保持する。
旧資料の「3台以上は対象外」という制限は撤回する。実装の順序と、製品として実現する範囲を混同しない。詳細は [製品定義](product-definition.md) を参照。

## 現行Mac/Windows版のユーザーフロー

### 初回

MacとWindowsへ導入 → WindowsでMacを選ぶ → Macの6桁コードをWindowsへ入力 → 入力権限を案内 → 机と同じ位置を選択 → カーソル移動とコピーを試す → 音声共有を任意で選ぶ。

接続コードの期限、試行回数制限、端末鍵の保存と削除、再認証時の挙動は実装前に仕様化する。表示用の短いコードだけを長期認証鍵にしてはならない。既存利用者のトークンからの移行も必要。

### 毎日

起動時に再接続。設定には接続相手と共有範囲を表示する。操作中の不要な通知は増やさない。
未接続・認証失敗・権限不足を区別して、次に押す操作を1つ示す。

### 困ったとき

通信を必要としない操作元端末への復帰操作を常に確保する。共有の一時停止は入力・クリップボード・ファイル・音声のどこまで止めるかを統一し、再開の状態も表示する。
診断の出力は利用者が操作したときだけ作成し、認証情報・クリップボード内容・入力文字を含めない。

| 検証 | 合格条件の案 | 確認方法 |
|---|---|---|
| 初回導入 | 説明なしの初見10名中9名以上が5分以内に接続 | 新規環境で観察。開発者の口頭補助が必要なら失敗として記録 |
| 通常利用 | 8時間の作業を3日間実施し、操作不能・意図しない入力・転送破損0件 | 操作・待機・転送・音声を組み合わせた実機試験 |
| 復旧 | 通信遮断時にもローカル復帰できる。再接続後に押しっぱなしが残らない | Wi-Fi切断、相手終了、ロック、スリープを各20回試す |
| 入力 | JIS/USと日本語/英語入力の規定操作がすべて成功 | コピー、貼付、修飾キー、記号、連続入力、ドラッグを固定手順で試験 |

| 試用継続 | 試用10名中8名以上が2週間後も日常利用 | 合意した試用調査で確認。自動収集を勝手に追加しない |

## 実装と判定の順序

1. 配布基盤：秘密設定を含めない、失敗を成功にしない、どのビルドか追跡できる。今回着手。
2. 初回導入：両OS共通の状態モデルと端末登録を設計し、新規ユーザーが端末を接続できるようにする。
3. 復旧：通信断・権限不足・ロック・スリープを再現し、操作を失わないことを確認する。
4. UI仕上げ：高DPI、フォーカス、読み上げ、表示倍率、長い文言とエラー状態を確認する。
5. 限定試用：固定した候補版で10名の観察試験を行い、不具合と利用継続を記録する。
6. 販売準備：署名・配布・更新・サポート・価格・公開説明を確定し、満たした範囲だけを案内する。

開発者証明書や販売アカウント、支払い、公開はユーザーの所有物・判断が必要。準備できるコードと検証は先に進め、契約・購入・公開を自動で行わない。

## 今回の実施結果

- 公開用のMac・Windowsパッケージから認証設定の自動同梱を撤去。
- ビルド失敗・署名失敗・配布検査失敗を終了コードで扱い、既存ZIPを保持。
- バージョン・コミット・実行ファイルハッシュを記録。Macは署名完了後のハッシュを.appの外へ保存し、署名とマニフェストを相互に壊さない構成。
- 配布検査の4テストが成功：両OSの構成、秘密設定と鍵・ログの拒否、改変検出、不正パスと重複の拒否。
- Cargoを意図的に失敗させた試験で、両OSの既存ZIPが変わらないことを確認。
- 0.23.0の両OS公開用ZIPの作成・内容検査が成功。Macのアドホック署名を検証済み。
- 稼働中アプリの更新・販売公開は行っていない。初回導入、高DPI、長時間利用など上記の出荷条件は未達・未検証を含む。

## 初回登録の工程

両OSの登録画面、OSによる資格情報保護、Windowsの認証後保存、Macのアクセシビリティ案内を追加。[実装と検証範囲](first-connection.md) を参照。6桁コードとSPAKE2による登録へ更新。初見ユーザーの新規環境での導入目標を達成したという判定ではない。
