# 仕様: 公開の不具合報告から作った耐性テスト(無通信切断・高速移動での誤切替)

- 書いた人: lead エージェント(2026-10-29)。参考 OSS のソースを読んでいるため実装には関わらない
- 実装する人: 参考 OSS のソースを読んでいないエージェント(Codex / gpt-6.1-terra)
- 根拠とした資料:
  - 似た製品の公開 issue に書かれた **症状だけ**(コードは参照しない):
    (1) 受信側が数秒の無通信で切断し、OS がバックグラウンドのアプリを間引くと誤切断する
    (2) カーソルを速く動かすと、画面端に着く前に相手へ切り替わる
  - Knit 自身のコード(`crates/win/src/session.rs` の 9 秒の読み出しタイムアウトと 3 秒ごとの ping、
    `crates/mac/src/main.rs` の 1 秒ごとの ping と 15 秒の pong 途絶判定、`crates/mac/src/tap.rs` の
    `abs_edge_reached` / `abs_edge_dist` / 境界判定)

## やること

### A. 無通信判定の定数を名前付きにし、関係をテストで固定する

Windows の受信側は「9 秒無音で切断」、Mac は「1 秒ごとに ping」「15 秒 pong 無しで切断」、
Windows は「3 秒ごとに ping」。これらは散らばった数値で、関係(切断判定は送信間隔の何倍か)が
コードから読めない。

- 共通側(`crates/common`)に定数をまとめる(例: `MAC_PING_INTERVAL`、`WIN_PING_INTERVAL`、`WIN_READ_SILENCE`、`MAC_PONG_SILENCE`)
- 両 OS からそれを参照するように置き換える(**値は変えない**)
- 単体テストで不変条件を固定する:
  - 受信側の無音判定は、相手の送信間隔の **3 倍以上**(1 回の取りこぼしで切れない)
  - Mac の pong 途絶判定は Windows の無音判定より長い(両側の判定がずれて片側だけ切れる状態を減らす)
- 値は変えないが、不変条件を満たしていない組み合わせがあれば報告する(直さない)

### B. 画面端の判定に「高速移動」のテストを足す

`crates/mac/src/tap.rs` の端到達判定(`abs_edge_reached` など)について、次の単体テストを足す:

- 大きな移動量(1 イベントで画面幅の 30% 以上)でも、カーソル座標が端に達していなければ到達にならない
- 端まであと 1px で止まった場合は到達にならない。ちょうど端は到達
- 斜めに速く動いて角付近を通った場合、設定された辺以外では到達にならない

既存の判定がこれらを満たさない場合は、テストを `#[ignore]` にせず、**失敗するテストとして書いた上で修正する**
(修正内容を報告)。満たしている場合はテストを足すだけ。

## やらないこと

- タイムアウト値の変更
- 端の判定アルゴリズムの作り直し(テストが落ちた場合の最小修正のみ)
