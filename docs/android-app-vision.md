# Knit for Android — 理想の定義

更新: 2026-09-28。製品定義([product-definition.md](product-definition.md))と
ビジョン([vision.md](vision.md))を Android タブレットへ当てはめた、アプリの目標像。
実装済み・検証済みの範囲を示すものではない。数値は未測定の提案値。

---

## 一文で

**机の上のタブレットを、MY DESK の「もう 1 枚の画面」にする。**

PC の横に立てたタブレットへ、カーソルがそのまま入っていく。Mac のキーボードで打てば、
タブレットに日本語が入る。Mac でコピーしたものが、タブレットで貼れる。
タブレットで見つけたページや写真が、ひと手間で PC に届く。
その間、利用者は「いまタブレットを触っている」と意識しない。

## North Star

**「これはタブレットだった」と意識する回数を 0 に近づける。**

新機能を考える時は「便利か」ではなく、
«この機能で、PC とタブレットの境界を 1 回消せるか» で判断する。

## 誰のために

- PC を 2 台以上使い分けながら、タブレットを机に立てて資料・チャット・動画・メモ・電子書籍に
  使っている人
- **開発者向けオプションを知らない、一般の人**。設定の奥にある項目を探させない。
  ターミナル、IP アドレス、ポート番号、サーバー/クライアントを一度も見せない
- 日本語で仕事をする人。JIS キーボード、かな/英数、変換が「PC と同じ気持ちよさ」で使える

## 7 つの約束

### 1. 入れて、つなぐだけ

ストアから入れて開くと、近くの Mac が見つかる。Mac に出た 6 桁を入れれば終わり。
必要な許可(ユーザー補助・Knit キーボード)は、**なぜ要るのかを一文で説明し、その設定画面まで
案内する**。許可を 1 つ飛ばしても、できる範囲で動き、何ができないかを示す。

### 2. 画面の端から、そのまま入れる

カーソルが PC の画面端を越えると、タブレットに Mac と同じ形のカーソルが現れる。
位置は Mac が絶対座標で決めるため、加速によるずれがない。越えた瞬間の 0.1 秒が
PC 同士と同じ感覚であること(ビジョン§23)を、Android でも最優先の品質にする。

### 3. タブレットの作法を尊重する

PC のふりをさせず、マウスとキーの操作を、タブレットで自然な操作へ訳す。

| PC での操作 | タブレットでの意味 |
|---|---|
| クリック | タップ |
| ドラッグ | なぞる(スワイプ・選択・並べ替え) |
| スクロール・二本指 | 慣性のあるスクロール |
| 右クリック | 長押し |
| ⌘C / ⌘V / ⌘A / ⌘Z | そのまま(Ctrl 相当) |
| ⌘[ / ⌘← | 戻る |
| ⌘Tab | 最近使ったアプリ |
| ⌘H・画面の端の特定位置 | ホーム(案) |

### 4. 日本語入力は第一級

Mac の JIS キーボードで、タブレットに PC と同じように日本語が入る。かな/英数キーが効き、
画面を移る時は Mac の入力状態を引き継ぐ(ビジョン§7 の IME Follow Cursor)。
変換候補の出し方と、タブレットの日本語入力(Gboard 等)との関係は、Android で最も難しい
設計課題であり、試作で解き方を決める。

### 5. 持ち物は一緒に移る

- **クリップボード**: テキストと画像。画面を移る瞬間に同期する
- **URL**: PC で見ているページを、タブレットでそのまま開く(Continue Here)。逆も
- **ファイル**: タブレットの共有メニューに「Mac へ送る」。PC からはファイルを掴んだまま
  タブレットへ越えれば届く(ダウンロードへ保存)
- **スクリーンショット**: タブレットで撮ったものを PC で使える

### 6. 見えて、止められて、取り消せる

何を共有しているか・どこへ送っているかを、タブレットの通知と Mac のメニューの両方で示す。
「一時停止」はワンタップ。登録はタブレット側からも Mac 側からも取り消せる。
音声・画面など、利用者が明示的に許可していないものは取らない。
未対応・権限不足・停止中・通信断は、それぞれ別の言葉で伝える。

### 7. 電池と常駐に誠実

PC とつながっていない時は、ほとんど何もしない。つながっている間だけ働く。
裏で止められやすい端末(Xiaomi 等)では、止められた事実と直し方を、利用者に分かる言葉で示す。

## 最初の 3 分(ここに極端にこだわる)

1. タブレットで Knit を入れて開く →「近くの Mac が見つかりました: 〇〇の MacBook」
2. Mac に表示された 6 桁を入れる →「つながりました」
3. 「Mac のマウスで操作するには、ユーザー補助で Knit を許可します」→ 設定画面へ案内 → 戻ると ✓
4. 「Mac のキーボードで入力するには、Knit キーボードを選びます」→ 同じく案内 → ✓
5. Mac の MY DESK にタブレットが現れる。ドラッグで置き場所を決める
6. 「マウスを右へ動かしてください」→ タブレットにカーソルが現れる
7. 「Mac でコピーしたものを、ここで貼り付けてみてください」→ 貼れる

ここで初めて「これは違う」と思ってもらう。

## 品質の目標(提案値・未測定)

| 項目 | 目標 |
|---|---|
| 初回の設定時間 | 説明書を読まずに 3 分以内。開発者向けオプションは 0 回 |
| 境界を越えてからカーソルが見えるまで | 1 フレーム + 通信往復以内。PC 同士と体感で区別できない |
| クリックの取りこぼし | 100 回中 0 回 |
| 日本語の入力 | Mac で打つ時と同じ手順で、変換・確定ができる |
| クリップボード | 画面を移ってから 0.5 秒以内に貼れる |
| 待機中の電池 | つながっていない間は、Knit の消費がほぼ見えない |

## 機能の地図(順に広げる)

1. **入る**: 発見・6 桁登録・状態表示・一時停止・取消
2. **操作する**: 疑似カーソル・タップ・ドラッグ・スクロール・長押し・キー・ショートカット・日本語
3. **持ち運ぶ**: クリップボード(テキスト・画像)・URL・ファイル・スクリーンショット
4. **集める**: タブレットの音を Mac で鳴らす(利用者の許可を得て)
5. **逆向き**: タブレットのタッチ・ペンで PC を操作する(製品定義の方向 1)

1〜3 がそろった時点で、一般の人に「使える」と言える。4〜5 は完成形に含める。

## 誠実に向き合う制約

| 制約(Android の仕組み) | 設計での答え |
|---|---|
| 通常のアプリは本物のポインタを出せない | ユーザー補助の重ね描きで、Mac と同じ形のカーソルを描く。ホバー表示はできないことを前提に作る |
| 入力は合成したタッチになる | 操作の対応表(約束 3)を丁寧に作り、慣性スクロールや長押しの時間を調整する |
| 裏のアプリはクリップボードを読めない | Knit キーボードが選ばれている間は読める。それ以外は画面を移る瞬間などアプリが前面にいる時に同期する |
| ユーザー補助の用途外利用は Google Play の審査が厳しい | 利用目的の明示と審査の準備。通らない場合の配布経路も用意する |
| 端末メーカーが裏のアプリを止める | 止められたことを検知し、端末ごとの直し方を案内する |
| 開発者向けオプションを使える人は、より本物に近い操作を望む | adb 方式を「精密モード」としてアプリから選べるようにする。同じタブレットは 1 台として扱う |

## やらないこと

- 開発者向けオプション・root・ターミナルを前提にする
- 画面をまるごと転送する遠隔操作アプリになる(タブレットは自分の画面で動く)
- タブレットを PC の追加画面・周辺機器にする。**各機器は自分の OS のまま使う**のが Knit の理想であり、
  タブレットは Android として机に参加する(2026-09-28 利用者の決定)
- 利用者の許可なく、音声・画面・通知・位置などを取る
- 使い方のデータを外へ送る

## 完成した姿

朝、PC の横にタブレットを立てる。何もしなくても Knit がつながる。
Windows で資料を書きながら、カーソルを右へ流すとタブレットのチャットに入り、
Mac のキーボードで日本語の返事を打つ。タブレットで見つけた記事の URL は、
次の瞬間 PC のブラウザで開いている。写真は共有メニューから Mac のダウンロードへ。
タブレットの音は、PC の音と一緒に、Mac につないだイヤホンから聞こえる。

利用者が考えているのは、何をしたいかだけ。
タブレットは、机の上のもう 1 枚の画面になっている。
