## 特に「飛びつく」と考える 5 つ(2026-09-28 利用者の意見で絞り込み・定義し直し)

### 1. 見た画面に、入力が行く

画面を見るだけで、キーボードの行き先がその機器に変わる。マウスを動かす必要すらない。
Mac のカメラで視線の向き(どの画面を見ているか)だけを端末内で推定し、映像は保存も送信もしない。

- 飛びつく理由: 「キーボードは最後にクリックした所へ行く」という Universal Control への不満の、
  一段先の答え。初めて体験した瞬間に魔法だと感じる
- 実現の芽: 画面単位の粗い判定で足りる(文字単位の視線追跡は不要)。macOS の Vision で顔の向きを推定
- 難しさ: 精度と誤判定の防止(見ながら別の画面へ打ちたい時)。明示的な有効化と、ひと目で分かる
  「いまの入力先」表示が必須

### 2. 貼る先に合わせて、形が変わる

Web の表を Excel に貼ればセルに分かれ、チャットに画像を貼れば自動で軽くなり、
コードは書式を保ったまま、住所は宛先の欄ごとに分かれる。機器をまたいでも同じ。

- 飛びつく理由: 貼った後の手直しが消える。機器をまたぐ時ほど形式が崩れやすい
- 実現の芽: クリップボードは複数の形式を同時に運べる。貼る先のアプリ名で形式を選ぶ
- 難しさ: アプリごとの対応表の作り込み

### 3. 席を立てば机ごと鍵がかかり、戻れば開く

スマホや腕時計を持って離れると、机の全部の機器が一斉にロックされる。戻れば Mac を開くだけで、
Windows とタブレットも使える状態に戻る。

- 飛びつく理由: 職場で「Windows だけロックし忘れ」が消える。安全と手間の両方に効く
- 実現の芽: Knit には画面ロックの連動が既にある(Mac→Windows)。離席は Bluetooth の距離で判定
- 難しさ: 自動の解除は安全設計が要る(Windows の資格情報の扱い)。まずロック側から

### 4. 同僚を、自分の机に招く

隣の人のマウスカーソルを、一時的に自分の画面へ入れる。2 人で 1 つのコードや資料を触る。
終わればワンクリックで帰す。

- 飛びつく理由: 画面共有の「そこじゃなくて、ここ」が消える。チームで広まる(口コミの起点)
- 実現の芽: Knit の複数台接続と操作権の管理(製品定義に既出)を、別の人に広げる
- 難しさ: 招待と操作権の見える化、切断時に確実に元へ戻すこと

---

### 5. 同じ通知は、いま使っている画面で 1 回だけ(2026-09-28 定義し直し)

メール・チャット・予定のように、アプリが各機器に入っていて全部に届く通知は、
**いまキーボードとマウスがある機器でだけ**出し、他の機器では静かに消す。
どこかで既読にしたり閉じたりすれば、他の機器の同じ通知も消える。
その機器にしか入っていないアプリの通知(Windows の更新、タブレットのアプリ等)は、そのまま出す。

- 飛びつく理由: 机に 3 台あると、1 通のメールで 3 回鳴る。重複を消すだけで、机が静かになる
- 設計の要点:
  - Knit は「いまどの機器を使っているか」を既に知っている(入力の行き先)
  - 同じ通知の判定: アプリの種類(Gmail と Outlook のように OS ごとに違うアプリも同じ「メール」)と、
    題名・本文の近さ、届いた時刻の近さで照合する。判定を誤った時に通知を失わないよう、
    消すのではなく「静かにする(音と表示を出さず、通知一覧には残す)」を既定にする
  - どのアプリを対象にするかは利用者が選べる(既定は、メール・チャット・予定)
- 実現の見立て(未検証):
  - Android: 通知を読む許可(NotificationListenerService)で、取り消し・スヌーズができる
  - Windows: UserNotificationListener で読み・削除ができる。ただしアプリとしての識別情報
    (パッケージ化)が要る可能性がある
  - Mac: 他アプリの通知を読む公式の手段がほぼない。Mac の通知は残し、Mac を使っていない間は
    集中モード(「ショートカット」経由で切替)で静かにする程度
- 難しさ: 同じ通知の照合の精度。Mac が読めないことによる非対称

## その他のアイデア

### 机の知能
- **机の記憶**: 「さっき Windows で開いていた見積書」「昨日タブレットで見たページ」を自然な言葉で
  全機器から探せる(Search My Desk の発展。索引は各機器の中だけで持つ)
- **机に頼む**: 「タブレットのこの表を Mac の Numbers に」「Windows で書き出した PDF を
  タブレットで開いて」を言葉で指示すると、機器をまたいで実行する
- **先回りの Continue Here**: 画面を移った時、直前に見ていたものの続きを移った先で開く用意をしておく

### 入力
- **声をどこへでも**: Mac の高精度な音声入力で話すと、Windows やタブレットの入力欄に日本語で入る
- **指癖の翻訳の学習**: 使い方から「このアプリではこのショートカット」を学び、OS の違いを自動で吸収する
- **機器をまたぐマクロ**: 「Mac でコピー → Windows の Excel に貼って保存」を 1 つの操作として記録・再生

### 画面と空間
- **ウィンドウを投げる**: ウィンドウを画面の端へはじくと、隣の機器で同じ文書・ページが開く
- **写真 1 枚で配置**: 机の写真を撮ると、画面の位置と大きさを推定して MY DESK の配置を作る
- **持ち歩く机**: ノート PC を職場に持っていくと、職場の配置と共有範囲へ自動で切り替わる。
  自宅の PC にも、必要なら安全な経路で手が届く

### 持ち物
- **どこでも棚**: どの画面にも端に「棚」があり、置いたものを別の機器で取り出せる
- **ダウンロードを使う場所へ**: タブレットで受け取ったファイルが、編集に使う PC へ届く
- **机じゅうのファイルを 1 つの窓で**: 全機器のファイルを 1 つの Finder の窓から見て開く

### 音
- **マイクは会議を追う**: 1 つのヘッドセットのマイクが、会議をしている機器へ自動でつながる
- **タブレットの通話を Mac のイヤホンで**

### 計算
- **Mac から Windows の GPU を使う**: 重い AI・3D の処理を、Mac の操作のまま Windows の GPU で動かす
  (ビジョン§15 Compute Handoff)

## 外したもの(2026-09-28 利用者の意見)

| アイデア | 扱い | 理由 |
|---|---|---|
| タブレットがペンタブ・追加の画面になる | 対象外 | 各機器は自分の OS のまま使うのが理想。タブレットを PC の周辺機器にする方向は趣旨と違う |
| 通知と集中を机ごと 1 つに(集める形) | 定義し直し → 下の 5 | メールやチャットはどの機器にも届くのが自然で、集めると重複が増える。困るのは「届かない」ではなく「何度も鳴る」 |
| 画面の文字をどこからでもコピー | 実現済みとみなす | OS の標準機能(Mac のテキスト認識表示、Windows の切り取り & スケッチ、Android の Google レンズ)でコピーし、Knit のクリップボード共有で別の機器へ貼れる。Knit 独自の文字認識は要らない |
