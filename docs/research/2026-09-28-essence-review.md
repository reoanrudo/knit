# 本質を疑う: いらない機能はつけない

作成: 2026-09-28。これまでに出した機能案([市場調査](2026-09-28-market-brainstorm.md)・
[未来志向](2026-09-28-future-ideas.md)・[机の一日](2026-09-28-desk-moments.md))を、
本質に照らして残すか捨てるかを判定した。**この文書の判定が、上の 3 文書より優先する。**

## 本質

**異なる OS の機器の間を、入力と持ち物(コピーしたもの・ファイル)が、
毎日確実に、何も考えずに行き来できること。**

- North Star「別の機器だと意識する回数を 0 に」と、市場調査の最大の不満「動くけれど信用できない」から導いた
- 新しい機能を足すより、この本質が**どの組み合わせでも・毎日・確実に**成り立つ範囲を広げる方が価値が大きい

## 判定の 5 つの問い

1. **境界が原因か**: 機器が複数あるから起きる不便か(1 台でも起きる不便は Knit の仕事ではない)
2. **毎日起きるか**: 対象の利用者に日常的に起きるか
3. **代わりがあるか**: OS・既存アプリ・一度の設定で足りないか
4. **信頼を削らないか**: カメラ・通知・SMS など、新しく敏感な権限を求めないか
5. **境界を意識させないか**: 機器の違いを利用者に意識させる作りになっていないか(North Star に反するものは捨てる)

## 判定

### 捨てる

| 案 | 落ちた問い | 理由 |
|---|---|---|
| 見た画面に入力が行く | 4・5 | カメラの権限を常に求める。誤判定で「思った所に入力されない」が起きれば、今の「カーソルのある所に入る」という単純で予測できる規則より悪い。魔法より予測できること |
| 貼る先に合わせて形が変わる | 1 | 1 台でも起きる不便。Knit の仕事は、書式(HTML・画像等)を**崩さずに運ぶ**ところまで |
| 同僚を机に招く | 1・2 | 自分の机の話ではない。別の製品(共同作業)になる |
| 通知の重複を消す | 3・4 | 各機器のアプリで一度通知を切れば足りる。全機器で通知を読む権限と、誤判定の危険に見合わない |
| 入力先のしるし | 5 | 「いま Windows です」と表示すること自体が、境界を意識させる |
| 認証コードを、いまの画面へ | 3・4 | 秘密を扱う権限が要る。パスキーやパスワード管理アプリが同じ問題を解きつつある |
| どこからでもミュート | 2・3 | 会議アプリごとの対応表が要り、壊れやすい。会議アプリ自身のショートカットで足りる |
| 貸し出し中 | 2・3 | まれ。接続先メニューで外せば足りる |
| 机の電池 | 1・3 | OS のウィジェットで足りる |
| 最近のダウンロードを、どこからでも | 2・3 | 頻度が低い。ファイルを掴んで越える・コピーで運べる |
| 同時に打つ | 2・3 | 一部の開発者だけ。専用の道具(tmux 等)がある |
| タブレットをペンタブ・追加画面に | 原則 | 各機器は自分の OS のまま使う(2026-09-28 利用者の決定) |

### 新機能ではなく「本質の品質」として直す

これらは機能ではない。境界を越える体験が壊れている箇所の修理であり、最優先で扱う。

| 案 | 本質のどこが壊れているか |
|---|---|
| 変換中の文字を置き去りにしない | 日本語を打ちながら越えると入力が壊れる |
| 越えた先が眠っていたら起こす(「机ごと起こす」を縮めたもの) | 越えようとしても、相手が眠っていると入力が届かない |
| 健康診断と自己修復の案内 | 「動くけれど信用できない」。権限の外れ・版違い・経路断を利用者が自力で直せない |
| 書式を崩さずに運ぶ(テキスト・画像・ファイル) | コピーしたものが別の機器で違う形になる |
| Android を開発者向けオプションなしで(有線 AOA・アプリ) | 一般の人には、そもそも越えられない |
| 日本語入力の完全対応(配列・英数/かな・変換/無変換) | 18 年分の不満。越えるたびに入力方式がずれる |

### 残す(本質の範囲を広げる)

| 案 | 理由 |
|---|---|
| 音を Mac に集める+機器ごとの音量 | 利用者が理想として求めた。境界が原因(機器ごとに別のスピーカー・イヤホン) |
| Mac のロックで机ごとロック(Android へ広げる) | 既存機能の延長。自動の解除はしない |

### 保留(聞き取りで起きていると確かめてから)

| 案 | 確かめること |
|---|---|
| カーソルはここ(振って見つける) | 画面が 3 つ以上の人に、見失いが本当に毎日起きているか。各 OS の標準機能で足りていないか |
| 再生キーは鳴っている機器へ | 音を集める機能を使った人が、再生キーで困るか |
| Knit ドングル | 別事業になる。会社 PC の需要の大きさ |

## 既存の機能も同じ物差しで見直す(候補・未判定)

新しい機能だけでなく、今ある機能にも同じ問いを当てるべき。判定は利用者と行う。

- **Search My Desk**(相手の PC のアプリを探して起動): 越えることが一瞬なら、相手の OS の
  ランチャーで足りるのではないか(問い 3)
- **env の設定項目 49 個**: 利用者が触るべきでない項目は既定値に固め、画面に出すものだけ残す
- **Continue Here / App Handoff**: 越えてからブラウザで開くのと比べて、どれだけ手間が減るか

## この判定から出てくる方針

1. 当面、新機能は足さない。「本質の品質」の 6 項目と、Android を一般の人へ届けることに集中する
2. 新しい案は、上の 5 つの問いを通ったものだけを検討する
3. 保留の案は、聞き取りで「その瞬間が本当に毎日起きている」と確かめてから判断する
