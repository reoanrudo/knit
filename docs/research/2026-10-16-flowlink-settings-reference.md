# FlowLink を参考にした Knit の設定GUI・追加機能調査

調査日: 2026-10-16。対象はローカルの FlowLink と Knit の作業ツリー。
Knit の HEAD は `200c41b`、FlowLink は最終照合時 `95286b7`。未コミット変更も含む。

ユーザーの選択により、今回は研究のみで終了する。以下の候補は採用・実装を決定したものではない。
アプリのソース、設定値、自動起動登録、認証情報は本調査では変更していない。
調査方法はソース・設計文書・UIモック画像の確認であり、FlowLink の実機GUI操作や共有機能の動作検証は行っていない。

## 1. 結論と訂正

Knit では、設定項目を大量に増やすより、次の4件を先に検討する価値がある。

| 優先候補 | 利用者への効果 | 相対的な難易度 |
|---|---|---|
| 設定の書き出し・読み込みをGUIにつなぐ | バックアップと引っ越しを画面から実行できる | 中。Mac の内部処理は存在するが、失敗時の扱いを再確認する必要がある |
| ログイン時の自動起動を画面で切り替える | インストール用スクリプトを使わず常駐を管理できる | 中〜高。Mac / Windows でOS側の処理が異なる |
| 接続ページ内に診断結果と対処を表示する | 接続設定と原因確認を同じ場所で行える | 中。既存診断の結果を構造化して表示する |
| 通知を種類別に設定する | 日常の通知量を調整できる | 中。発生箇所を分類し、重要なエラーを見落とさない設計が必要 |

初回の説明・レポートには、次の誤りがあったため訂正した。

- **設定の書き出し・読み込みは、内部関数があるだけでGUIは未配線。** [内部関数][knit-io]の呼出し元はテストのみだった。[利用ガイド][knit-usage]は画面操作ができるように記載しており、現行実装と一致しない。「既に利用可能なので追加不要」という初回判定を取り消す。
- 端末の個別解除は、接続一覧や配置情報の削除では実現しない。現行は登録時に長期接続キーを渡す方式であり、認証の取消しには別の設計が必要。[登録処理][knit-pairing]と[暗号化処理][knit-secure]を参照。
- 音声の既存経路は Windows → Mac。[音声受信実装][knit-audio]に合わせて提案を修正した。Mac → Windows の音声送出を前提にしない。
- Knit は設定画面下部にバージョンを既に表示している。[表示実装][knit-version]を確認したため、「バージョン表示を新設する」という提案を取り消す。

## 2. FlowLink の実装範囲

FlowLink は Tauri 実行時とブラウザプレビューで画面実装を切り替える。[画面の振り分け][flow-app]だけでなく、各項目が実際の処理に使われているかを区別した。

| 画面・タブ | ネイティブ側で確認できた内容 | 注意点 |
|---|---|---|
| ホーム | 実際の端末・接続情報を表示 | 共有機能のカードは「未接続」と明示。[ホーム実装][flow-home] |
| デバイス: 配置レイアウト／デバイス一覧 | 端末グループのドラッグ、位置X/Y、縮尺、ディスプレイ情報、接続区間の編集、配置の明示保存 | 名前・アイコン色などブラウザ版の項目すべてがネイティブ版にあるわけではない。[配置実装][flow-devices] |
| 操作・入力: 基本／詳細／ショートカット／ジェスチャー | 入力設定の取得・保存、手動キーマップ、キーキャプチャ | 保存できることと実OS入力への適用は別。下記参照。[入力設定][flow-input] |
| クリップボード: 基本／履歴／フィルタ／同期ルール | 同じ画面を利用。OSクリップボードの取得やローカル履歴の処理がある | 端末間の同期や除外アプリの実効性まで実装済みとはいえない。画面全体を「完全なモック」とするのも不正確。[画面実装][flow-app] |
| ファイル転送: 基本／保存先／転送履歴／詳細 | プレビュー用UI | 実端末間の転送に未接続。保存先や帯域上限などはアイデアとして扱う |
| 音声: 再生／マイク共有／詳細 | プレビュー用UI。Web Audioによるローカルのテスト音生成がある | 音声のネットワーク疎通確認ではない。実ストリームは未接続 |
| ネットワーク: 基本／接続方法／詳細 | LAN設定、接続候補、ペアリング、インライン診断、表示名・ポートの保存 | 診断は取得済み状態から組み立てる。ボタン操作が新たな疎通測定を行うとは限らない。[実装][flow-network] |
| セキュリティ | 信頼済み端末一覧、個別失効、端末ごとの受信権限、公開鍵指紋 | 端末ごとの証明書・信頼情報に基づく。Knit の共有キー方式とは異なる。[実装][flow-security] |
| 設定: 一般／外観／通知／アカウント／バージョン | 自動起動、外観、設定の入出力・リセット、通知設定の保存 | 通知配信・更新サービスなどは未接続。言語の保存だけで全文の翻訳完了とは判断しない。[実装][flow-settings] |

[FlowLink の実装記録][flow-progress]では、感度・移動しきい値・スクロール方向などは入力処理への反映が記録されている。
一方、コーナー移動・配列・Fnキー・ショートカットのグローバル登録・ジェスチャー・通知配信には未接続の項目がある。
古い残件一覧と新しい実装記録が食い違う箇所があり、今回の調査では現在のソースを優先した。
実OSでの効果については、記録とコード確認を根拠とし、今回動作確認したとは扱わない。

また、FlowLink の[履歴プライバシー処理][flow-privacy]と[診断ロジック][flow-diagnosis]には、Knit からの移植である旨が記載されている。
この2点は新機能の発見ではなく、FlowLink 側での見せ方や追加部分を参考にする対象である。

## 3. Knit の設定GUIの現状

Mac / Windows は「接続・画面配置・切替・共有・その他」の5ページ構成。
[設定画面の方針][knit-design]では、初期設定・日常の操作感・動作確認に関係する項目を優先し、調整値を増やしすぎない方針を採っている。

| ページ | Mac | Windows の主な差分 |
|---|---|---|
| 接続 | 役割2択、接続状態、Android状態、端末登録、接続先アドレスと「保存して再接続」 | 自分のアドレスを表示。初回登録の導線はMacと異なる |
| 画面配置 | ドラッグで辺・モニターを選択、クリックで操作対象を選択、現在値を表示 | 8方位の配置キャンバス。Mac側へ配置変更を送る |
| 切替 | F6／F8／F13／右⌘、特定方式で滞在時間50〜1000msを表示 | 切替キー・滞在時間はMac側の遠隔設定で、接続が必要 |
| 共有 | テキストと画像、ファイル、受信音声の再生、再生音量、ローカルコピーの履歴 | 自分の音声を相手へ送出。「相手側の設定」の操作もある |
| その他 | 日本語／English、再起動、登録の全初期化、設定の全初期化 | 日本語のみ。ログ・診断ボタンは設定内にもある |

出典: [Mac 設定UI][knit-ui]、[Windows 設定UI][knit-win-ui]。
Mac の診断導線はメニューバーで、結果は別アラートに出る。[診断の実装][knit-diag-ui]を確認した。
設定画面には版表示・保存結果・出元別の保存エラーが既にある。

Mac の設定保存先は `~/.config/knit/preferences.json`、Windows は `%LOCALAPPDATA%\Knit\preferences.json`。
Mac の設定変更は原則自動保存、接続先は明示保存。環境変数が優先する項目は固定状態を表示する。
Windows のローカル保存は音声・クリップボード・ファイル・役割の4項目が中心で、Macの設定全体とは対称ではない。[Windows 保存処理][knit-win-prefs]

[共通の永続化処理][knit-persist]にはアトミック書き込みと破損ファイルの退避がある。
ただし、ファイルが途中で破損しないことと、「メモリ反映・OS反映・保存」の全処理が一括で成功することは別である。

## 4. 追加機能候補と実装上の条件

難易度はソース確認による相対評価であり、日数見積もりではない。P0は先に検討する候補、P1は次点、P2は設計変更を伴う研究項目とする。

### 4.1 P0: 先に検討する4件

| ID | 候補 | 参考になる点 | Knitでの最小案・注意点 | 難易度 |
|---|---|---|---|---|
| P0-1 | 設定の書き出し・読み込み | FlowLink の[厳密なインポート検査][flow-import]とデータ管理UI | Macの既存関数へファイル選択UIを接続。ただし現在の読み込みはメモリに適用後に保存するため、保存失敗時の復元を設計する。秘密情報を含めない。Windowsは別途設計が必要 | 中 |
| P0-2 | ログイン時の自動起動 | FlowLink の専用操作と結果表示 | 現在は[Macインストール処理][knit-install]と[Windowsインストール処理][knit-win-install]が登録を担当。設定画面でOSの実登録状態を確認し、登録・解除の失敗も表示する。Windowsの復帰監視タスクも考慮する | 中〜高 |
| P0-3 | 接続画面内の診断 | FlowLink の項目別表示と実在の操作名を指す対処文 | Knitの既存診断を再利用し、原因・状態・対処を接続ページ内へ表示。長時間処理は非同期化。表示用の文だけでなく構造化した結果を返す | 中 |
| P0-4 | 通知の種類別設定 | FlowLink の接続／切断／転送完了／失敗／セキュリティ／更新の分類 | まず日常的な接続・転送完了の通知を調整対象にする。通知OFFでも重要な失敗や登録要求が画面から消えないようにする。FlowLinkのOS通知配信は未実装なので、配信コードを移せるわけではない | 中 |

[設定入出力の既存関数][knit-io]は再利用候補だが、インポートの未知項目を無視する方針と、FlowLinkの全項目一致を求める方針は異なる。
厳密にすれば常に良いとは限らない。旧形式の補完・新しい形式の扱い・不正値の拒否を分け、設定の移行互換性を維持する必要がある。

### 4.2 P1: 次点の8件

| 候補 | 最小案・制約 | 難易度 |
|---|---|---|
| サウンドテスト | 「Mac内の出力確認」と「Windows → Macの経路確認」を区別する。後者はWindows側でテスト音を生成し、通常の音声経路でMacへ戻す設計が必要。FlowLinkのローカル音を鳴らすだけのUIでは代用できない。実際に聞こえたかは利用者が確認する | 中／経路全体は高 |
| キー変換プレビュー | 現在の変換設定に基づき⌘C→Ctrl+Cなどを表示。固定の説明文と実際の変換結果を区別する。アプリ別の例外もあるため「必ずこのキーになる」と誤表示しない | 中 |
| 受信ファイルの保存先・完了後の動作 | 受信する端末自身に設定。保存先の権限・空き容量・同名処理を確認し、完了時にフォルダを開くかを選べるようにする。FlowLinkはUIアイデアの参考のみ | 中〜高 |
| 履歴の保存件数・保存期間 | 現行50件を基準に件数・期間を選択可能にする案。画像容量の上限と機密情報の保護は維持。全体のリセットとは分ける。FlowLinkの画面項目を根拠に「端末間履歴同期まで実装済み」とは扱わない | 中 |
| 切替キーの入力登録 | 4候補を残し「ほかのキー」を入力で設定。Knitのキーコード方式とFlowLinkの修飾キー組合せは別なので、文字列をそのまま移さない。緊急復帰キー・既存操作との競合検査が必要 | 中〜高 |
| コピー共有から除外するアプリの管理 | 機密文字列の自動判定とアプリ単位の除外は別機能。送信と履歴保存のどちらを止めるかを明示し、OSごとのアプリ識別・取得権限を設計する。FlowLink側も未配線のUI項目がある | 高 |
| 接続品質の推移 | 既存RTTを時系列で表示。通信品質を未測定の損失率や安定性の数字で装わない。FlowLinkのプレビューの固定値は転用しない | 中 |
| 更新の自動確認トグル | 現在の環境変数による設定をGUIから扱う。環境変数優先時は固定状態を示す。バージョン表示は既にあるため追加しない | 中 |

### 4.3 P2: 認証・プロトコル設計を伴う3件

| 候補 | 参考になる点 | Knitで先に解決すること | 難易度 |
|---|---|---|---|
| 信頼済み端末の個別失効 | FlowLink の端末ごとの証明書・指紋・信頼記録と失効操作 | Knitは[登録時に既存の長期キーを渡す][knit-pairing]方式。[PeerEntry][knit-peer]は接続中の情報で、信頼台帳ではない。行・配置・接続を消しても鍵は失効しない。端末固有の認証と取消し、既存端末の移行、全経路の接続拒否を設計する必要がある。初回の「一覧から消せばよい」という案は撤回 | 高 |
| 端末ごとの共有権限 | FlowLink の入力・クリップボード・ファイル・音声・マイクの受信許可 | KnitのPC単位の共有制限を、認証された端末単位へ分ける必要がある。本線・bulk・音声で同じ相手と権限を確認し、UIだけで禁止したように見せない | 高 |
| 画面端の一部分だけを接続するエディタ | FlowLink のPortal編集と重複・無効区間の検証 | Knitにも区間値の保存はあるので完全な新機能とはしない。複数端末・モニター・正規化座標との関係、重複検出、戻り方向、既存配置との互換を比較してGUI化の範囲を決める | 高 |

個別失効の代わりに「一時切断」「画面配置から除去」を提供する案はあるが、それを「信頼解除」と呼ぶことはできない。
既存の[全登録初期化][knit-reset]は接続キーを作り直して全端末に再登録を求める。これとは効果を区別する。

## 5. GUIの構成と品質の参考点

FlowLinkの9画面構成をそのまま導入する必要はない。まずKnitの5ページを維持し、接続診断は「接続」、共有内容・履歴・ファイルは「共有」、自動起動・通知・データ管理は「その他」にまとめる案が適している。
項目が増える場合は詳細部分を折りたたみ、常用しない調整を常に表示しない。

FlowLinkから参考にできる仕組みは次のとおり。

- 設定変更を確定値から表示し、成功・失敗・処理中を共通部品で示す。[状態管理][flow-state]は参考になるが、処理中の追加操作を早期returnで捨てるため、高頻度のスライダ入力へ無条件に転用しない。
- 配置の編集中データと確定済みデータを分け、明示保存・破棄・競合表示を行う。保存時はリビジョンを検査する。[配置UI][flow-devices]と[状態管理][flow-state]を参照。
- キー入力ではフォーカス中の案内、Escapeでの中止、受け付けないキーの理由を表示する。[入力UI][flow-input]を参照。
- 型・値域・バージョンを検証してから設定を適用する。[インポート検査][flow-import]を参考にしつつ、Knitの移行方針は別に決める。

Knitに既にある保存状態行、エラー表示、環境変数優先の注記、ja/en切替時の入力保持、プレビューモードは維持する。
FlowLinkの方式を優位と決めつけて置き換えない。

## 6. 保留・今回は勧めない項目

ポインター感度、スクロール方向、配列、修飾キーの手動変換、ジェスチャー一覧、画面端の細かな判定値は、KnitでGUIを簡素化した経緯がある。[設定画面の方針][knit-design]を見直す際は、既定値で困る具体例があるかを判断材料にする。

アカウント・契約表示、一般のインターネット接続、マイク共有、テーマやアクセント色の独自設定、同時転送数・帯域制限、起動時ページ、設定の横断検索は今回の優先候補に含めない。
これは恒久的な不採用ではなく、現在のKnitの目的・構成に対する調査上の提案である。

## 7. 今後実装する場合の確認事項

現時点で実装には着手しない。再開時には対象を選び、未コミット変更と最新のFlowLinkを再確認してから設計する。

1. 設定入出力: 秘密情報が含まれず、不正な入力や保存失敗で確定値を失わないこと。
2. 自動起動: OSの登録状態と表示が一致し、無効化しても復帰監視タスクから起動しないこと。
3. 診断: 結果表示が入力を妨げず、対処文の操作が実在すること。
4. 通知: 日常通知を止めても、権限不足・登録要求・重要な失敗を見落とさないこと。
5. 音声: ローカルテストとWindows → Macの経路テストを区別すること。音を出す試験は利用者の事前承認後に行う。
6. 個別失効: 対象の全経路で再接続が拒否され、他端末への影響も明確であること。
7. GUI: Mac/Windows、日本語/英語、狭いウィンドウ、キーボード操作、OSの表示倍率で崩れないこと。

本調査中はビルド・回帰テスト・音声テスト・OS設定の変更を実施していない。
既存ドキュメントの操作案内との不一致も研究結果として記録し、利用ガイド自体は変更していない。
