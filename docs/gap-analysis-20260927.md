# 理想と現行実装の対応表(ギャップ分析)

更新: 2026-09-27(改善ループ 563)。product-definition.md「次の設計作業は、全体の対応表…」への応答。
判定は 2026-09-27 時点のコードと実機検証記録(vision.md 実装状況メモ・improvement-log)に基づく私の評価。

判定記号:
- **実装済み** = 主要動作を実装し実機検証した(理想の細部の試験が残る場合を含む)
- **部分** = 中心となる一部が動く。理想の過半には未達
- **未実装** = 対応する実装がない
- **再設計** = 現行の「Mac=サーバ・Windows=参加・2台・共通トークン」構成のままだと
  追加では届かず、端末モデル/操作権の再設計が前提になるもの

## 読み取れる構造

1. **下の層ほど届いている**(§19 の思想どおり): 入力(I)・データ(D)は実装済みが並ぶ。
   ただし I02/I03/D03 は「世界対応・整合性」の質が次の段階。
2. **真の壁は端末モデル**: 2 台・共通トークン・方向固定の現行構成は、3 台以上・
   端末別鍵・操作権(M02)・遠隔(E04)・失効(L03)のすべての前提を塞いでいる。
   機能追加では解けず、product-definition.md の言う「端末登録と操作権」の設計が先。
3. **My Desk が無い**: 製品の中心画面(配置・共有先の選択)は未実装。現行の
   メニューバー/トレイ/検索窓は便利だが「机」の概念をユーザーに見せていない。
4. **製品品質(P/L)が丸ごと前方**: 世界向け・アクセシビリティ・署名・診断・退会は
   「動く試作」と「完成した製品」の境界そのもので、ここが 0 である限り製品ではない。

## 次の設計作業への優先順位(私の提案)

1. 端末モデルと操作権(G01/G02/M02/M03): 端末 ID・端末別鍵・許可・失効・操作権の
   状態機械。既存の pairing/credentials を土台に拡張。これが他の再設計項目の鍵
2. My Desk 画面(M01/C02 の統合 UI): 配置グラフ+共有先選択。現行の設定分散を集約
3. OS 別実装境界の明示(F03): 物理キー/文字/コマンドの共通形式(prepare の前提)
4. その後でタブレット(E04/T 系)と製品品質(P/L)を段階的に
