# knit 操作ガイド

Mac のキーボード/トラックパッドで Windows デスクトップを操作するツール。
Mac=サーバ(TCP 24900 で待ち受け)、Windows=クライアント(接続し続ける逆転構成)。

## 基本操作

| 操作 | 動作 |
|------|------|
| Mac のカーソルを画面右端へ | Windows へ切替(同寸法の高さで境界を越える) |
| Windows のカーソルを画面左端へ | Mac へ戻る(同じ高さで右端内側に復帰) |
| F13 キー | 手動トグル(切替が効かないときの保険) |

切替まわりの細部の挙動:

- 切替はカーソルが Mac 画面の境界そのものに達したときだけ起きる(境界手前の帯では
  どんな速度でも切り替わらない)。Windows 側の復帰判定も左端のピクセル(x = 0)で、
  実際にカーソルが動いたときだけ判定する
- 接続のある辺(配置で指定した辺)以外の 3 辺はただの壁: 触れてもカーソルは
  画面端で止まるだけで、切替もカーソルの隠蔽も起きない
- 切替時にドラッグしていた場合は Windows 側へ左ボタンを離すイベントを送り、
  誤ドラッグを持ち込まない
- Mac への復帰直後 400ms は右端判定を無効化し、切替の往復チャタリングを防止
- Windows 側の左端復帰は 0.7 秒のクールダウン付き(連打による往復を防止)。
  通常の選択やウィンドウのドラッグ中は復帰しない。ファイルを掴んでいる場合は
  下記のファイル引き継ぎでMacへ戻れる。

## キーボード

- Mac の修飾キーは自動変換: Cmd→Ctrl、Option→Alt、Control→Win、Shift→Shift
  (Win 側では「Mac と同じ修飾の組合せ」になるよう差分で押し替え、復帰時に全解放)
- **右⌘キーは Windows の右 Ctrl として動きます**(既定)。`KNIT_RCMD_CTRL=0` で無効
  (右⌘をホットキーに設定している場合はホットキーが優先される)
- **かなキー**(Mac keycode 104)→ Windows 側の IME を ON(ひらがな入力)
- **英数キー**(Mac keycode 102)→ Windows 側の IME を OFF(英字入力)
- **切替時に Mac の IME 状態を引き継ぐ**(IME Follow Cursor): Windows へ画面を
  移る瞬間、Mac がかな入力中なら Windows の IME を ON、英数モードなら OFF へ
  合わせる。**Apple 純正の英字レイアウト(「U.S.」等)も OFF へ合わせます**
  (IME が乗っていないため日本語入力の英数モードと同じ扱い)。サードパーティ IME
  や他言語の入力ソースの間は Windows 側を変えず、Mac 側ログに
  `[ime] 入力ソース(...)は同期対象外` を出します(かな/英数キーで手動切替できます)
  (`KNIT_IME_SYNC=0` で無効化)
  - フォアグラウンドウィンドウのデフォルト IME ウィンドウへ
    `WM_IME_CONTROL`(IMC_SETOPENSTATUS)を送る(方向指定が確実な定番手法)
  - IME ウィンドウが取れないアプリ(コンソール等)では、手動のかな/英数キーは
    半角/全角相当のトグルへフォールバックし、**切替時の自動同期はスキップ**します
    (方向を保証できないトグルで同期すると、切替のたびに IME が反転し続けるため)
  - 成否は Mac 側ログ(`[ime] kc=104 (かな) 転送` 等)と Windows 側ログ
    (`[ime] WM_IME_CONTROL open=true -> sent` 等)で切り分けられる
- 変換・確定(Enter/Space)はそのまま転送され Windows の IME が処理する
- **Mac(JIS 配列)の ¥ キーは、Windows では半角の `\` として入力されます**
  (Windows の JIS キーボードには ¥ 単体キーが無く、対応するキーは `\` として
  扱われるため)。全角の￥は Windows 側の IME の変換候補で入力してください。
  この割り当てを変更する設定は現状ありません(将来課題です)

## マウス

- **Windows 側はサブピクセル累積方式**: 受け取った移動量(dx, dy)を f64 で累積し、
  整数部だけ SendInput で注入、端数は次のイベントへ持ち越す。1px 未満の
  トラックパッドの細かい動きも消えず滑らかに動く
- **Mac 側は delta 積算 + 間欠同期で切替判定**: タップコールバック内で移動 delta を
  積算して自前のカーソル位置を追跡し、16 イベントに 1 回だけ実カーソル位置へ同期
  する(毎イベントの位置取得は負荷が高くカクつくため)。切替の瞬間だけ実位置を
  取って正確な高さを Windows 側へ引き継ぐ
- 移動倍率は `KNIT_MOUSE_SCALE` で調整(既定 1.0)

## 有線直結(遅延・揺らぎの低減)

WiFi の瞬間的な揺らぎがカーソルのカクつきの原因になる場合、Mac と Windows を
有線で結ぶと改善します。**通常の USB ケーブルでの Mac⇄PC 直結はできません**
(USB はホスト↔デバイス接続のため、PC 同士は双方ホストになる)。
実用的な選択肢:

| 方法 | 内容 | 備考 |
|---|---|---|
| **USB-LAN アダプタ×2 + LAN ケーブル** | 両側に変換アダプタを付け直結(またはルータへ有線接続) | 最も安価・確実。推奨 |
| **Thunderbolt ブリッジ** | Thunderbolt 対応 PC と Thunderbolt ケーブルで直結 | 高速。Windows 側の Thunderbolt Networking 対応が必要 |
| USB リンクケーブル | ブリッジチップ入りの転送用ケーブル | Mac 対応品がほぼ無い |

いずれも IP リンクが張れれば Knit はそのまま動きます(TCP のみのため)。
現在の経路の遅延は、Mac の設定「接続」の状態行(または Windows のステータス窓)に
「遅延 Nms」として出ます。**この数値は ping 往復(RTT)であり、キー入力から
Windows での反映までの時間(入力経路の遅延)は含まれません**(入力経路の遅延を
直接測る手段は現状ありません。下の [既知の制限](#既知の制限) 参照)。
80ms 超が続くようなら Wi-Fi ではなく有線の検討サインです。
直結 IP は Windows 側 `.env` の `KNIT_HOST` に **カンマ区切りで並べて** 指定できます
(例: `KNIT_HOST=169.254.10.2,100.100.10.9`)。起動のたびに全候補へ同時に接続を試み、
最初に繋がった経路(=遅延の小さい経路)を使います。
Mac の IP は `ifconfig` で確認(Thunderbolt ブリッジは bridge0、USB-LAN は en*)。
接続先は **LAN 自動発見(UDP 24903)と `KNIT_HOST` の併用**です。接続のたびにまず同じ
LAN の Mac を探し(最初の応答 or 600ms)、見つかった LAN IP を先頭に `KNIT_HOST` の
候補を並べて同時接続レースへかけます。つまり **同じ LAN では常に LAN 直**が最速で
採用されます。

**Tailscale 経路は既定で無効**です(外出先から自宅機を操作しない運用のため。離れた
場所の Windows が勝手に再接続して境界に現れるのを防ぐ)。外出先から使うときだけ
`KNIT_ALLOW_TS=1` を指定すると、`KNIT_HOST` の Tailscale IP へのフォールバックと
Tailscale 経路からの受け入れが有効になります。

## Mac 流ショートカットの自動翻訳(Windows 画面操作中)

Mac の指癖がそのまま Windows で通るように、以下を翻訳します:

| Mac の操作 | Windows での動作 |
|---|---|
| ⌘← / ⌘→ | Home / End(行頭・行末) |
| ⌘↑ / ⌘↓ | Ctrl+Home / Ctrl+End(文書の先頭・末尾) |
| ⌥← / ⌥→ | Ctrl+← / Ctrl+→(単語単位の移動) |
| ⌘M / ⌘H | Win+↓(ウィンドウの最小化) |
| ⌘Q | Alt+F4(ウィンドウを閉じる) |
| ⌘] / ⌘[ | ブラウザの次/前のタブ(Ctrl(+Shift)+Tab) |
| ⌘⇧4 / ⌘⇧3 | スクリーンショット(Win+Shift+S の切取り) |
| ⌘⇧←→ / ⌘⇧↑↓ | 行選択 / 文書選択(Shift+Home/End 等) |
| ⌥⇧←→ | 単語単位の選択 |
| ⌘⌥Esc | タスクマネージャ(Ctrl+Shift+Esc) |
| ⌘Ctrl+Q | 画面ロック(Win+L) |
| fn+F11 | デスクトップ表示(Win+D) |
| ⌘Space | Win+Space(IME/言語の切替) |
| ⌘C/⌘V/⌘A 等 | Ctrl+C/V/A(⌘→Ctrl 自動変換、従来どおり) |

トラックパッドジェスチャ: 横スワイプ=戻る/進む、Ctrl+2本指スクロール=
ズーム(Chrome/Edge 等)、3本指ドラッグ=ドラッグ(アクセシビリティ設定で有効時)。
ピンチ等の追加ジェスチャは macOS が一般アプリに公開していないため現状非対応。

## スクロール

- Mac のスクロールのピクセル delta を除数(既定 60・設定ウィンドウのスライダーで可変)で変換して
  ノッチ単位へ変換し、**0.05 ノッチ(=6 ホイールユニット)刻み**で Windows へ送る(端数は持ち越し。
  プレシジョンタッチパッドと同じ高解像度スクロール。低速でもカクつかない)
- Windows 側はノッチ × 120 ホイールユニットで注入
- 除数を大きくすると遅くなる(40〜200 程度で調整)

## クリップボード(画面を移る時に同期)

- **画面を移る瞬間に同期します**(Deskflow と同じ方式)。Mac で ⌘C → Windows へ移ると
  Mac の内容が Windows に渡り、Windows で Ctrl+C → Mac へ戻ると Windows の内容が Mac に渡る。
  コピーのたびには送らないため、Mac の中だけのコピペで大きなファイルが流れることはない
- 対応形式: テキスト(1MB まで)・画像(両方向)・ファイル(両方向、1回の合計 10GiB まで)
- ファイルは1件でも合計でも最大10GiB(10,737,418,240バイト)。Mac・Windowsの両方を更新すると利用できる。
  256KiBずつ読み書きするため、ファイル全体をメモリに載せない。
- **相手側の空き容量は送る前に確認できません**(事前の空き容量問い合わせは未対応)。
  1GiB 以上の送信では開始時に「N 件・合計 ○○ を送信します」と通知して規模を伝えます。
  受信側は保存先(Downloads/Knit)に転送量以上の空き容量が必要です。空きが足りないと
  そのファイルだけ「保存できませんでした(保存先の空き容量が不足)」として通知されます。
  空きが心配なときは相手の Downloads/Knit の空きを確認するか、10GiB 級は数回に分割して送ってください
- 受信ファイルは各 PC の Downloads/Knit に保存します(**保存先の変更はできません。将来課題です**)。
  同名のファイルは上書きせず「名前 (1).拡張子」として保存し、完了通知に
  「同名の N 件は『名前 (n)』として保存しました」と件数が表示されます。
  同名のフォルダも「名前 (1)」として別に作成します(既存フォルダへ内容をマージしません。
  フォルダ内の同名はそれぞれ「名前 (1)」で回避)。
  外部から来たファイルとして Mac は quarantine、Windows は Zone.Identifier を付ける
  (開く時に OS の確認が出る)
- 転送の途中で切断・中止した場合、相手側には「受信済みの N 件は保存されています」
  という部分報告の通知が出ます(掴みドラッグ経路は受け取った分をすべて削除します)。
  途中から再開する機能(レジューム)はありません。最初から送り直してください
- Win→Mac は CRLF を LF へ正規化して書き込む。相手から受信した内容は送り返さない
- 設定窓でクリップボード共有を OFF にすると、Windows 側も送らない
- (実験的)同じ PC で ollaya が動いている場合、テキストの送信前にローカルの判定モデルで
  機密らしさ(パスワード・API キー等)を検査し、確度が高いときだけ送信を止めます(smartguard)。
  判定は完全にローカルで、テキストが外へ出ることはありません。ollaya が無ければ従来どおり。
  誤検知時は `KNIT_SMART_SECRET=0` で無効化。対象はテキストのみ(画像・ファイルは従来どおり)
- Mac→Win は LF を CRLF へ正規化して書き込む(メモ帳等で貼り付けた時の行送りの乱れを防ぐ)

## クリップボード履歴(Universal Clipboard History)

> **履歴は平文(暗号化なし)でファイルに保存されます。Mac でのコピーは既定で記録 ON です。**
> 見られたくないコピーがある環境では、次の 2 つを使ってください:
> ① 記録を止める: 設定「共有」の「Macのコピーを履歴に残す」をオフ
> (環境変数 `KNIT_LOCAL_HISTORY=0` でも止められます)、
> ② 全消去: 履歴メニューの「履歴を消す」(保存ファイルごと消えます)。
> 履歴メニューにも「※履歴は平文で保存されています」の表示を常時出しています

- **Mac でコピーしたものは、画面を越えなくても全て履歴に記録されます**(Clipy などの履歴アプリは不要です)。
  加えて、画面を越えて送信・受信したテキスト・URL・**ファイル参照・画像**も記録されます
  (新しい順 10 件を表示、上限 50 件)。パスワード管理アプリなどが「機密」と印を付けたコピーは記録しません。
  Knit を起動した時点で既にあったコピーは記録しません。
  **Windows はトレイ右クリック →「クリップボード履歴」、Mac はメニューバー →「クリップボード履歴」**
  から選ぶと、その PC のクリップボードへ復元できます(貼り付け操作で使えます)
- 項目は「3分前・Mac・本文の先頭…」の形式。ファイルは「ファイル・名前 ほかN件」、
  画像は「画像・NKB」と種別が分かるように出ます。どちらの PC で発生したコピーか一目で分かります
- 履歴は起動しても保持されます(Windows: %LOCALAPPDATA%\Knit\history.json、
  Mac: ~/.config/knit/history.json)。「履歴を消す」で全消去できます
- **履歴ファイルは平文(暗号化なし)で保存されます**。他のユーザーに読まれないよう
  ファイルは所有者のみの権限(Mac は 0600・ディレクトリは 0700、Windows は
  プロファイル既定の ACL)で書かれますが、同じユーザーで動くソフトからは読める
  状態です。残したくないコピーは「Macのコピーを履歴に残す」をオフにするか、
  こまめに「履歴を消す」を使ってください
- カード番号らしい桁並び(Luhn チェックを通る 13〜19 桁)を含むコピーは、履歴に
  保存されません(送信・貼り付けは妨げません)。8 桁以上の連続する数字
  (ワンタイムコード・口座番号のほか、日付(YYYYMMDD)・注文番号・ISBN なども)
  は、**桁の部分を ● に置き換えて**履歴に残ります(長文の一部でも丸ごと消えない
  ようにするため)。**履歴から復元・再コピーするとマスク後の文字列になり、元の
  数字は戻りません**。数字を含む URL も桁部分がマスクされます。本文全体が数字
  だけ(認証コード単体など)のコピーは、マスクで中身が残らないため記録しません
- 画像の本体は各 PC のデータ領域(Windows: %LOCALAPPDATA%\Knit\images、
  Mac: ~/.config/knit/images)に内容ハッシュ名で保存され、新しい 60 件へ
  自動的に刈り込まれます(履歴から選ぶと画像が戻ります)
- 機密判定(smartguard)で止めたテキストや「共有しない」印のコピーは履歴に載りません
- 1MB(バイト数)を超えるテキストは同期も履歴も対象外です。超えている場合は
  「N文字・NKB。上限は1MB(日本語の長文では約35万文字)です」の通知で伝えます

## 越境 App Handoff(実験的)

- `KNIT_APP_HANDOFF=1` を設定すると、**Windows へ切り替えた瞬間**に Mac の
  最前面アプリと同じアプリを Windows でも起動します(«作業を別 PC へ投げた» 体感の
  第一歩。ビジョン§12)。例: Mac の「Terminal」→ Windows の「Windows Terminal」
- 照合は Windows 側のアプリ一覧(スタートメニューの列挙)に対する完全一致→部分一致(Mac 名 4 文字以上。一覧が未取得なら要求を送り、次回の切替に備えます)。
  対応するアプリが無ければ何もしません(ログに記録)
- 勝手にアプリが開く驚きを避けるため**既定は無効**です

## 境界越えの賢い判定(速度)

- 境界へ**速く**進んだ場合(目安 1200px/s 以上)は「意図的な越え」とみなし、
  滞在待ち(switchDelay)やダブルタップをスキップして即座に切替します。
  ゆっくり端に触れた場合だけ従来どおりの誤爆防止が働きます
- どちらで切替したかはログに記録されます(`[mode] WINDOWS (edge, fast)`)。
- 素早い動きで意図せず切り替わってしまうときは `KNIT_FAST_EDGE=0` で
  この速度例外を無効化できます(ダブルタップ・滞在待ちが常に有効になる)。
  速度の閾値(1200px/s)自体は現状環境変数では変更できません

## Windowsのファイルを掴んでMacへ渡す

1. 共有中のMacのマウス・トラックパッドで、WindowsのExplorerからファイルを掴む。
2. Macと接する画面端の細い青い帯へ運び、押したまま待つ。
3. 転送が終わるとMacへ移り、ファイルのアイコンを掴んだ状態になる。
4. Finderで開いたフォルダ内や、ファイルを受け取れるアプリで離す。

- 原本を残してコピーする。複数選択は64項目まで、合計10GiBまで。
- **フォルダも渡せる**(プロトコル14対応版同士)。中身はフォルダ構造ごと
  (相対パス付き・展開後512ファイルまで)届く。**空のフォルダも再現される**
  (プロトコル15対応版同士。旧版の相手には空のフォルダは届かない)。
- 大きなファイルでは、掴んだまま境界(青い帯)で待つ間に実体の転送が行われ、
  完了後に Mac へ移る(進捗は通知で表示)。待ち時間はサイズに比例し、数GiB では
  数十秒以上かかることがある。準備中に端から戻す・ボタンを離すと取り消す。
- 転送中は進捗が出る(Mac のメニューバーに %、Windows のツールチップ・ステータス画面)。
  **Esc キー(または Mac のメニュー「転送を中止する」)で中止**できる。
  **転送中の中止では、相手側の部分ファイルは削除される**。転送が完了して
  Mac 側で掴んでいる状態からの取り消し(Esc)では、受信済みのファイルは
  Mac の Downloads/Knit に残る。
- 受信したファイルは内容のハッシュ(BLAKE2s)で検証してから保存され、更新日時も保持される。
  保存できないファイル(空き容量不足・名前の衝突など)は通知で知らされる。
- Macへ移った後はEscで取り消せる(受信済みのファイルは Downloads/Knit に残る)。
  この Windows→Mac の経路では通常のクリップボードは書き換えない。
  逆向きの [Mac→Windows](#macのファイルを掴んでwindowsへ渡す) では、ドロップできない
  場所で離したときに Windows のクリップボードへ載る(そちらの節を参照)。
- シンボリックリンク・エイリアスは(リンク先を実体として送らず)スキップされる。
  スキップした項目があるときは通知で件数と名前が表示される。
- 仮想ファイル(Outlook 等)は未対応。通常のファイルとフォルダだけを選ぶ。
- 両アプリのプロトコル12対応版が必要。旧版との接続では従来のコピー・貼り付けを利用する。
- この機能はファイルを逆方向へ渡すもの。Windowsに接続した別のマウスでMacを操作する機能は含まない。

## Macのファイルを掴んでWindowsへ渡す

Windows のファイルを Mac へ渡すのと逆方向も、同じ感覚で渡せる。

1. Mac の Finder などでファイル(またはフォルダ)を掴んだまま、Windows と接する
   画面端(既定は右端)へ運ぶ。
2. 境界で押したまま待つ。この間に実体の転送が行われる(進捗は Mac のメニューバーと
   Windows 側の表示に出る)。待ち時間はサイズに比例し、数GiB では数十秒以上かかる
   ことがある。
3. 転送が完了すると Windows へ移り、ファイルを掴んだ状態になる。エクスプローラーの
   フォルダ内や、ファイルを受け取れるアプリで離す。

- 原本を残してコピーする。1回64項目まで、展開後512ファイルまで、合計10GiBまで。
  上限を超えるときは掴んだ時点で通知され、越境しない。
- フォルダも渡せる(Windows→Mac と同じくプロトコル14対応版同士。空のフォルダは
  プロトコル15以降)。シンボリックリンク等はスキップされ、通知で件数と名前が
  表示される。
- 受信したファイルは Windows の Downloads\Knit に保存される(保存先の変更は不可)。
- 転送中は Mac のメニュー「転送を中止する」で中止できる。**転送中の中止では、
  相手側(Windows)の部分ファイルは削除される**。転送完了後(Windows で掴んでいる
  状態)で Esc を押すとドラッグを取り消せるが、この場合は受信済みのファイルは
  Downloads\Knit に残る。
- **ドロップできない場所で離したときは、代わりに Windows のクリップボードへファイルが
  載る**(次の Ctrl+V で貼り付け可。実体は Downloads\Knit にも保存済み)。転送が完了した
  時点でボタンを既に離していた場合も、同じ扱いになる。このときだけ Windows の
  クリップボードが書き換わる。

## Continue Here(ブラウザの引継ぎ)

Windows 画面を操作している時に **⌥⌘T** を押すと、Mac の前面ブラウザの現在ページを
**Windows の既定ブラウザで開きます**。「Mac で見ていたページを Windows でもう一度
探す」手間を 1 回で消します(ビジョン§11)。

- 対応ブラウザ(Mac 側の読み取り): Safari / Google Chrome / Microsoft Edge / Brave
  (Firefox は URL の AppleScript 対応が無いため対象外)。**読み取るのは実際に
  前面にあるブラウザ**です(裏で起動しているだけのブラウザは読み取りません)
- 開く側は Windows の**既定ブラウザ**に関連付けに従う
- 転送は `http`/`https` のみ(上限 2048 文字)。送信側・受信側の両方で検査する
- 初回は Mac 側で「自動化の許可」(System Events とブラウザ)のダイアログが
  出ます。Windows 画面を操作している間は気づきにくいため、失敗時は Mac に
  通知を出します
- ⌥⌘T は専用ショートカットとして Mac・Windows のどちらにも転送されません
  (Ctrl+Alt+T 系のショートカットと衝突する場合は `KNIT_CONTINUE_HERE=0`)
- `KNIT_CONTINUE_HERE=0` で無効化

## 音量・メディアキー(Windows 画面操作中)

Windows 画面を操作している間、Mac 本体キーボードの音量キーとメディアキーは
**Windows 側の操作**として転送されます(Mac 側では変わらない):

| Mac のキー(fn を併用、または「F1〜F12 を標準のファンクションキーとして使用」が OFF) | Windows での動作 |
|---|---|
| F10/F11/F12(音量) | Windows の音量ミュート/下げ/上げ |
| F7 / F8 / F9(メディア) | 前の曲へ / 再生・一時停止 / 次の曲へ |

fn を押さない F7〜F12 は従来どおり F キーとして渡ります。
F1〜F6 は macOS が輝度・キーボード照明のメディアイベントとして配るため、Windows では
対応する F1/F2・F5/F6 キーとして届け直します(実験的。輝度そのものは Windows 側の
画面を変えられないため)。F3/F4 は OS が直接処理するためイベントが届かないことがあります

## 音声共有(Windows の音を Mac で再生)

Windows の再生音を Mac で鳴らします(既定 ON。独立ポート 24901・暗号化)。
接続中は Windows 側のスピーカーを自動ミュートして Mac のみで鳴らし、切断で元に戻します。
Windows 側が異常終了(強制終了・電源断)してミュートが残った場合も、
Windows 側 Knit の**次回起動時に自動で元に戻ります**。

- **Mac で鳴る音量の調整**: 設定「共有」の**「再生音量」スライダ**(0〜200%)。
  Windows 画面を操作している間は Mac の音量キーが Windows 側へ転送されるため、
  この場で調整するにはスライダを使います(初期値は環境変数 `KNIT_AUDIO_GAIN`)
- **遅延の目安**: おおむね 90〜130ms です(デバイスとネットワークによります)。
  映像よりわずかに遅れて聞こえるのは正常で、時間が経っても増えない設計です
- **Wi-Fi が不安定な時**: 届く間に合わない音は**古い方から捨てて**遅延を溜めない
  ため、音が途切れることがあります(有線直結や安定した Wi-Fi では起きにくい)
- **出力デバイスの切替(Bluetooth ヘッドフォン等)**: 切替直後は数秒無音になる
  ことがあります(Windows 側は最長2秒後にキャプチャを作り直すため)。
  Mac 側の出力先変更への追従は未検証です。音が出ない場合は設定「共有」の
  音声チェックを一度 OFF → ON してください
- **二重発音の注意**: 本線(入力の経路)だけが瞬断した場合、音声の経路は生きて
  いるためミュートは維持されますが、環境によっては Windows の音が
  両方から聞こえることがあります。その場合は Windows 側を手動ミュートするか、
  Mac 側の設定で一時的に音声共有を OFF にしてください
- Windows の**システム通知音**は環境によって既定デバイス以外へ流れる場合が
  あります。音が来ない場合は Windows のサウンド設定で既定デバイスを確認してください

## 実機での確認手順(IME 引継ぎ・Continue Here)

どちらも「画面を移る時だけ」動く機能のため、次の手順で確認します:

**IME 引継ぎ(IME Follow Cursor)**

1. Mac を日本語入力(かなモード)にしてから Windows 画面へ移る
   → Windows 側が日本語入力になっている(Windows のログに
   `[ime] mac の状態へ同期: かな(ON)`)
2. Mac 側で英数キーを押してから Windows 画面へ移る
   → Windows 側が英字入力になっている(`英数(OFF)` のログ)
3. Mac を英字レイアウト(日本語入力ではない)にして Windows へ移る
   → Windows 側の IME が OFF になる(ログ `[ime] Mac の状態を Windows へ同期: 英数(OFF)`)
4. 対象外の入力ソース(サードパーティ IME 等)のまま Windows へ移る
   → Windows 側の IME は変化しない(Mac 側ログに `[ime] 入力ソース(...)は同期対象外` が出る)

**Continue Here(⌥⌘T)**

1. Mac の Safari/Chrome/Edge/Brave で任意のページを開く
2. Windows 画面へ移り、⌥⌘T を押す
3. Windows の既定ブラウザで同じページが開く(Mac 側ログに `[url] Continue Here: 送信しました`)
   - Firefox は Mac 側の読み取り対象外(開く側は Windows の既定ブラウザなら何でも可)

## 接続の方向(Windows をホストにする)

既定では Mac が待ち受け側(ホスト)で、Windows が接続しに行きます。ネットワークの作り方に応じて
接続の方向を反転できます。例えば Mac 側にファイアウォールや AP 隔離があって待ち受けられないときは、
Windows をホストにします。

- **Windows 側**: 設定「接続」の「このPCがホスト: Macがこのパソコンへ接続しに来る」を選ぶ。
  切り替えて Knit が再起動すると、このPCは接続を待ち受けます(「Macがホスト: このPCがMacへ接続しに行く(既定)」
  を選び直すと接続側へ戻る)
- **Mac 側**: メニューバーの Knit アイコンの「{Windows の名前} をホストにする」を押す。Knit を再起動すると、
  この Mac は Windows(ホスト)へ接続しに行きます(もう一度押すと待ち受けに戻る)
- 両方を切り替えたら、両方の Knit を再起動します。同じ LAN なら接続先の指定は不要です
  (自動発見が働きます。見つからないときは Mac 側で `KNIT_HOST` に Windows の IP を設定)

`KNIT_ROLE=server`(Windows)/ `KNIT_ROLE=client`(Mac)の環境変数でも同じ切り替えができ、
環境変数は設定より優先されます。

## 登録の管理(登録した端末を締め出す)

登録をやり直したい・貸していた端末に接続させたくない、というときは、Mac の設定「接続」の
**「すべての登録を初期化…」**を使います。確認のダイアログを通すと、この Mac の接続キーを
キーチェーンから削除して新しいキーを作り直し、Knit を再起動します。

- 接続キーは全端末で共通の共有鍵のため、**初期化した時点で、いままで登録した全端末が
  接続できなくなります**(いま接続中の相手も切断されます)。旧いキーを知っていても
  以後の接続はすべて拒否されます
- 再び使いたい端末は、設定「接続」の「端末を登録…」から再度登録してください
  (新しいキーが渡されます)
- 環境変数 `KNIT_TOKEN` を設定して運用している場合、キーチェーンの初期化では
  締め出せないため、画面は初期化を中断して案内を出します。設定元の `KNIT_TOKEN` を
  削除して Knit を再起動してください
- 端末ごとに個別に剥奪する(1台だけ締め出す)機能は未実装です。1台だけ外したいときも
  全登録の初期化と再登録で対応してください

## 接続の挙動

- 経路: 本線 TCP 24900(入力・制御)/ 音声 TCP 24901 / ファイル・画像 TCP 24902 /
  自動発見 UDP 24903。ファイル転送は本線と別経路のため、転送中もマウスが止まらない
- **全経路を暗号化**(Noise プロトコル。トークンから導いた鍵で相互認証し、トークン自体は
  回線に流れない)。接続を受け入れるのは既定で LAN・有線直結のみ
  (`KNIT_ALLOW_TS=1` で Tailscale も、`KNIT_ALLOW_ANY=1` で全許可)
- 生存確認は双方向だが役割が違う: **Mac は 1 秒毎に ping を送り**、応答(pong)が
  **15 秒**途絶したら張り直す。**Windows は読み出しタイムアウト 9 秒**(Mac からの
  ping が 9 秒届かなければ経路断)。切断後の再試行の待ちは最長 10 秒
- Windows の解像度変更・モニター抜き差しを検知すると Mac へ通知し、
  カーソル速度の換算と Windows 画面内の仮想カーソル位置を自動で追従させる
- Mac のスリープ復帰を検知すると即座に張り直す(復帰直後の死んだ接続を待たない)。
  検知は単調時計と壁時計のずれ(3 秒超)によるため、時計が進み続ける浅いスリープでは
  検知できず、上の生存確認(pong 15 秒途絶)で切れてから張り直しになる
- Tailscale の経路が直結から中継(DERP)に落ちると通知する(遅延が数倍になるため。
  Tailscale 許可時のみ)
- ping 往復(RTT)が 80ms 超の状態が 10 秒以上続くと「遅延が続いています」と一度だけ
  通知する(10 分に 1 回まで)。Wi-Fi の場合は [有線直結](#有線直結遅延揺らぎの低減)
  のサインとしてください
- Windows モード中に切断・Mac の画面ロックが起きたら即 Mac モードへ復帰(入力の閉じ込め防止)
- 画面を離れる時は、Windows 側で押下中の全キー・ボタンを解放する(押しっぱなしを残さない)

## 設定と環境変数

ふだんの調整は、メニューバーの Knit の設定ウィンドウ(⌘,)で完結します。環境変数は、
設定ウィンドウにない項目を変えたい時と、うまく動かない時の救済にだけ使います
(knit-mac の起動時に設定。Windows 側の変数は `.env` へ書きます)。

### 設定ウィンドウにある項目(環境変数でも初期値を指定できる)

| 変数 | 既定 | 説明 |
|------|------|------|
| `KNIT_SIDE` | right | 接続先の位置。right/left/up/down + upright/lowright(右下)/upleft/lowleft。「画面配置」の配置エディタ(ドラッグ)が同じ結果を視覚的に作れる |
| `KNIT_SWITCH_MODE` | edge | 切替方式。`edge`=画面の端とF13の両方 / `hotkey`=F13のみで切替し、切替後は境界を超えても戻らないロック状態(F13で戻すまで固定) |
| `KNIT_SCROLL_DIV` | 60 | スクロール速度の除数(初期値)。大きくすると遅い。実行中は設定ウィンドウのスライダーで可変 |
| `KNIT_SCROLL_FLIP` | (未設定) | スクロール方向。未設定=起動時の macOS の設定(自然スクロール ON/OFF)に合わせる。起動中に切り替えた場合は設定画面を開き直すと反映する。`1` で Windows 標準へ固定 |
| `KNIT_CLIP` | 1 | クリップボード共有。0 で無効 |
| `KNIT_AUDIO` | 1 | Windows の音声を Mac で再生する。0 で無効(両側で指定) |
| `KNIT_AUDIO_GAIN` | 1.0 | Mac で再生する音量の初期値(0.0〜2.0。1.0=100%)。実行中は設定「共有」のスライダで可変 |
| `KNIT_MUTE_SPK` | 1 | 接続中に Windows 側スピーカーを自動ミュートする。0 で無効(音は両方の PC から出る) |

## 共有範囲の制限(会社の PC などを「入力だけ」でつなぐ)

キーボードとマウスの共有は常に有効です。クリップボード・ファイル・音声は、その PC ごとに
許可する範囲を決められます。**制限した PC の側で送受信が止まる**ため、
相手の設定に関係なく、その PC の内容は外へ出ず、外の内容も入ってきません。

### 設定ウィンドウから

- **Mac:** 設定 →「共有」の「テキストと画像」「ファイルの受け渡し」「接続先の音声をこのMacで再生」
- **Windows:** 設定 →「共有」の「このPCが共有する内容」(テキストと画像 / ファイルの受け渡し)と「音声転送」
  (会社の PC は、この PC 側の設定が常に優先されます。Mac の設定には従いません)

設定は自動で保存されます。次の環境変数は、設定ウィンドウより強い**上限**として働きます。

### 環境変数(上限。管理者や、設定を固定したい時に)

| 設定 | 動作 |
|------|------|
| (未設定)/ `all` | すべて共有(既定) |
| `input` | 入力のみ。クリップボード(テキスト・画像)・ファイル・ドラッグ・音声をすべて止める |
| `clipboard,files,audio` のうち許可するものを `,` `+` 空白で並べる | 入力 + 指定したものだけ共有(例: `KNIT_SHARE=clipboard`) |

- 設定する場所: Mac は `~/.config/knit/env`、Windows は `%USERPROFILE%\knit\.env` に `KNIT_SHARE=input` と書き、Knit を再起動します
- 綴り間違いなど読めない指定は、共有が開かないよう **「入力のみ」として扱います**(起動ログに `[share]` で表示)
- 音声を共有しない PC は、相手の設定にかかわらず自分のスピーカーをミュートしません
- 制限中に相手から届いたデータは、保存せず捨てます(接続は保たれます)
- 環境変数で禁じた項目は、設定ウィンドウでは変更できません(オフ・操作不可で表示されます)
- 設定は PC 単位です。接続先ごとに変える設定は未実装です。Android アプリは未対応です

## ホットキーロックモード(オプション)

`./scripts/restart-mac.sh --hotkey` で起動すると、画面境界での自動切替をやめ、
**ホットキー1つだけで Mac⇄Windows を切替**できます。切替後は境界を超えても
勝手に切り替わらないロック状態になり、もう一度ホットキーを押すまで戻りません
(Windows 側で左端に行っても戻りません)。`--edge` で従来モードに戻ります。

- 既定のホットキーは **F13**(Mac keycode 105)。MacBook 内蔵キーボードに F13 が
  無い場合は `KNIT_HOTKEY_KC` で変更できます(例: 右 Cmd=54、F6=97)
  - 起動例: `KNIT_HOTKEY_KC=54 ./scripts/restart-mac.sh --diag --hotkey`
- 起動ログに `switch_mode=hotkey(ロック) hotkey_kc=105` の形式で反映状況が出ます

## うまく動かない時

**つながらない・切れた・切れて戻らないときは、まずアプリ内の診断を開いてください。**
Mac はメニューバーの Knit の「接続を診断…」、Windows はタスクトレイ右クリックの
「接続診断」です。原因を順に確かめて、対処を教えます。

- 切断は自動で再接続します(再試行の待ちは最長 10 秒)。**切断が 60 秒を超えたときだけ
  通知を出します**。数秒〜数十秒の切断は放置して構いません
- 未接続が続くとき、Mac のメニュー状態行と Windows のステータス窓に
  「再試行まで N秒」「相手を N分見つけられません」が出ます。1 分を超えても
  つながらない場合は診断、そして下の [自動発見が届かない環境(AP隔離・ゲストWi-Fi)](#自動発見が届かない環境ap隔離ゲストwi-fi) を確認してください

まず [接続の挙動](#接続の挙動) と [既知の制限](#既知の制限) も確認してください。それでも直らない時は、
次の環境変数で個別の機能を調整・停止できます。

**音声まわりで困った時**は [音声共有](#音声共有windows-の音を-mac-で再生) も参照してください:

- Windows の音が Mac から出ない: Windows のサウンド設定で既定デバイスを確認 →
  Mac の設定「共有」で音声を一度 OFF → ON(接続とキャプチャを作り直します)
- ヘッドフォン等への切替直後は数秒無音になることがあります(仕様。
  数秒待っても戻らない場合は上の ON/OFF 切り直し)
- 音声共有が有効な間に本線(入力の経路)だけ切断すると、環境によって
  Windows の音が両方から鳴ることがあります(音声の経路が生きているため。
  その場合は Windows 側を手動ミュート、または Mac 側設定で一時的に音声共有を OFF)
- 音が途切れる: Wi-Fi が不安定なとき、届く間に合わない音は古い方から捨てられる
  ためです。[有線直結](#有線直結遅延揺らぎの低減) が効果があります
- Windows 側を強制終了した後にスピーカーが鳴らない: 次回の Knit 起動時に
  自動で元に戻ります(戻らない場合は Windows 側のサウンド設定を手動確認)

### 自動発見が届かない環境(AP隔離・ゲストWi-Fi)

Wi-Fi の設定で端末同士の通信が分離されている(AP アイソレーション・AP 分離)や、
ゲスト用ネットワークでは、相手を自動で見つけるブロードキャスト(UDP 24903)が
届きません。診断で「相手を見つけられない」系の結果が出て、両 PC が同じ Wi-Fi に
いるはずなのに繋がらないときは、この環境の可能性があります。**IP の直接指定が
正解です**(トラブルではなく、そのネットワークの正しい使い方):

1. **Mac の IP を確認**: システム設定 > Wi-Fi > 詳細(IP アドレスの
   「192.168.x.x」等。ターミナルでは `ifconfig | grep "inet "` でも出ます)
2. **Windows 側の `.env` へ書く**: `%USERPROFILE%\knit\.env` に
   `KNIT_HOST=192.168.1.23` の形式で書く(カンマ区切りで複数可。
   例: `KNIT_HOST=169.254.10.2,100.100.10.9`)
3. **Windows 側の Knit を再起動**する

- Mac が接続しに行く側(「接続の方向」で Windows をホストにした場合)は、
  Mac 側の `~/.config/knit/env` へ同じ形式で Windows の IP を書きます
  (Windows の IP は 設定 > ネットワークとインターネット > Wi-Fi で確認)
- AP 分離が厳しいネットワークでは TCP すら届かないことがあります。その場合は
  [有線直結](#有線直結遅延揺らぎの低減)(USB-LAN アダプタ×2 が安価で確実)か
  [接続の方向](#接続の方向windows-をホストにする) の反転を試してください
- Wi-Fi の再接続で IP が変わることがあります。変わったら付け直すか、ルータの
  DHCP 固定割当(IP の予約)で固定するのが楽です
- 設定画面からの IP 指定(GUI での入力)は未実装です(将来課題)

## 改善ループ(開発者用)

変更→検証の 1 サイクルを回す手順:

```bash
# Mac 側: ビルド鮮度保証付きで再起動(引数はそのまま knit-mac へ)
# 起動直後に異常終了した場合はログ末尾とともに WARN を表示する
./scripts/restart-mac.sh --diag

# Windows 側: ビルド → 停止 → 配布 → 対話起動
./scripts/deploy-win.sh

# 自動検証(プロセス/接続/クリップボード双方向/IMEログ/diag集計)
./scripts/verify.sh
```

- `restart-mac.sh` / `deploy-win.sh` は起動のたび BUILD_ID(日時+git短縮sha)を
  埋め込み、`/tmp/knit-mac.log`・`C:\Users\<user>\knit\knit-win.log` の
  先頭行(`[info] knit-mac ...` / `[info] knit-win ...`)で配布物の鮮度を確認できる
- `--diag` は毎秒
  `mode/moves/keys/sent/scrolls/warp_fixed/switches/cursor/moving` をログ出力。
  境界問題の切り分けは `warp_fixed`(カーソル巻き戻し回数)と
  `moving`(WIN中は false が正常)で行う。`switches` はモード切替回数、
  `scrolls` はスクロール送信回数。
  なおこれらの回数と「遅延 Nms」表示(ping 往復 RTT)で入力遅延を推測できますが、
  キー入力から Windows での反映までの時間を直接測るものではありません
- 起動ログにスクロール除数・マウス倍率・切替判定幅・クリップボード上限の
  調整値がまとめて出る(`[info] screen ... scroll_div=... mouse_scale=...`)
- `verify.sh` は Windows へ ssh できない場合、該当項目を NG にせず WARN 扱いにして
  続行する(検証不能と失敗を区別)
- `check-mouse.sh` は切替後に Mac 側カーソルが凍結(抑制)されているかを検証する
- ログ: Mac=`/tmp/knit-mac.log`、Windows=`C:\Users\<user>\knit\knit-win.log`
  (ssh home で type)。Mac 側ログの `[rtt]` 行は ping 往復(RTT)が 80ms を超えた
  ときの時刻別記録です。カクつきがネットワーク遅延によるかの切り分けに使えます
  (`scripts/stability-report.sh` で断の統計と合わせて集計できます)

## 開発者・ゲーム向けの自動切替

- **ターミナルでの Control**: Windows の前面が Windows Terminal・cmd・PowerShell・WSL 等の間は、
  Mac の Control を Windows の Ctrl として送る(Ctrl+A/E/R/C がそのまま効く)。それ以外のアプリでは
  従来どおり Win キー。対象は `KNIT_CTRL_APPS` で変更できる
- **ゲームモード**: Windows でカーソルが閉じ込められた(FPS 等)、または全画面でカーソルが
  1.5 秒以上隠れた間は相対移動で送る(視点回転が効く)。戻るにはホットキーを使う
- **Secure Input の通知**: Mac でパスワード欄などの保護入力が有効だと、キーボードを Windows へ
  送れない。Windows へ移った時にこの状態なら、原因のアプリ名を通知する

## アップデート

メニューバーの Knit から「アップデートを確認…」を選ぶと、新しい版を確認します。見つかると項目が
「Knit X.Y.Z に更新…」に変わり、選ぶと取得・検査して自動で入れ替わります(失敗時は旧版のまま)。
起動後と6時間ごとにも静かに確認し、新しい版があれば通知します。止めるには `KNIT_AUTO_UPDATE=0`。
端末からは `~/Applications/Knit.app/Contents/MacOS/Knit --update`。
Windows はタスクトレイのメニュー、Android は設定画面の「アップデート」から同様に更新できます
(Android は最後に OS の確認画面が出ます)。

**更新確認だけが、PC 間通信とは別にインターネットへ出る通信です。** GitHub Releases
(https://github.com/reoanrudo/knit) へ HTTPS で接続し、署名検証済みの更新情報だけを取得します。
Mac と Windows 間の入力・クリップボード・ファイル・音声の通信が外部へ出ることはありません。
更新確認も含めて外への通信を完全に止めるには、`KNIT_AUTO_UPDATE=0` を設定したうえで
メニューからの手動確認を行わないでください(手動確認は接続します)。

## 既知の制限

- リッチテキスト(書式付き)のコピーは未対応(プレーンテキストとして渡る)
- 音声の Mac 側出力先変更(再生中にヘッドフォンへ切り替える等)は未検証。
  切替直後は数秒無音になることがあり、音が出ない場合は設定「共有」の
  音声チェックを一度 OFF → ON してください(Windows 側の既定デバイス変化は
  最長2秒後に検知して作り直します)
- ファイル転送のレジューム(途中からの再開)は未対応。切断・中止で届かなかった分は
  最初から送り直す必要がある(届いて保存済みの分は残る。中断時の部分報告通知で
  何件保存されたか分かる)
- 転送の中止は接続の切断として伝わる設計のため、**中止・切断の直後すぐの再送は
  「ファイル転送経路が未接続」になり得る**。送信側は接続の回復を最大60秒待って
  自動で再試行するが、それでも失敗するときは相手が再接続してから(通常は数秒〜
  数十秒)もう一度送ってください
- 相手側の空き容量を送る前に問い合わせる機能は未対応(1GiB 以上の送信開始時に
  規模を通知するので、事前に受け手の保存先(Downloads/Knit)の空きを確認してください)。
  受信ファイルの保存先を変更する設定も未対応(将来課題)
- IME ウィンドウが取れないアプリでは、手動のかな/英数キーだけが効きます
  (トグル動作。切替時の自動同期はスキップされるため反転しません)
- Mac→Windows 方向のみ自動引継ぎ。Windows で変えた IME 状態は Mac へ戻る時に
  Mac へは反映されない(かな/英数キーで手動切替)
- UAC 昇格中のプロセスには UIPI により SendInput が弾かれ、ロック画面・UAC の確認画面は
  保護デスクトップのため届かない。**操作補助**(install.bat を管理者として実行すると導入される
  SYSTEM 常駐の `knit_input` タスク)があれば Mac から操作できる。未導入のときは、Mac から
  操作中にこれらが出ると制御を Mac へ自動で戻す(固まらない)。
  操作補助は UAC の「はい」も押せる強い権限なので、接続元は同一セッション・導入時に記録した
  knit-win.exe のパス・対話ユーザーのパイプ権限に限る。その exe が一般ユーザーの書き込める
  場所(%USERPROFILE%\knit)にある限り、同じユーザーで動く悪意あるプログラムが同名 exe を
  差し替える余地は残る(残リスク)。撤去は `knit-win.exe --uninstall-input-helper`
- Windows 側は DPI 非対応のまま動作する(座標は OS が拡大率に応じて換算する)
- 入力経路自体の遅延(キー入力から Windows での反映までの時間)を測る手段は
  ありません。見える化されているのは ping 往復(RTT)と切替・送信の回数のみです。
  タイムスタンプを入力イベントに載せて通す計測はプロトコル変更を要するため
  将来課題です
