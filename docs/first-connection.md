# 初回登録：自動検出と6桁コード

## 利用者の操作

1. MacでKnitを起動し、「Windowsを登録」を開く。
2. WindowsでKnitを起動し、近くのMacを選ぶ。見つからなければMacのIPv4アドレスを入力する。
3. Macに表示された6桁コードをWindowsへ入力し、「登録する」を押す。
4. Macの完了画面を閉じ、必要なアクセシビリティ権限を許可する。以後は保存した鍵で自動接続する。

長いキーの手動受け渡しは不要。IPは接続先を探すための情報であり、接続を許可する鍵にはしない。
探索が届かないTailscale・AP隔離環境ではIPを使う。同じLANでは次回以降も自動探索し、IP変更に対応する。手動経路のIPが変わった場合は接続設定の更新が必要。

## 登録通信

- Macの登録画面を開いている間だけ、TCP/UDP 24904で待ち受ける。通常の入力通信と分離。
- コードはOS乱数から生成し、5分・最大3接続試行・成功1回で終了。閉じると探索応答と進行中ソケットも停止する。新しく開くとコードも変わる。
- 探索は表示名と送信元アドレスのみ。コード・長期キー・コードのハッシュを公開しない。探索結果そのものは信頼しない。
- SPAKE2（`spake2 0.4.0`）で短いコードから共有セッション鍵を導出する。毎回新しい状態を生成し、招待IDと役割を紐付ける。
- 導出した鍵で通常接続と同じNoise方式・ライブラリでハンドシェイクを行い、相互に鍵の一致を確認した暗号化経路で長期キーを渡す。6桁コードを直接NoiseのPSKにしない。
- Windowsは認証済みの鍵をOS保護領域へ保存してから応答する。Macはその応答を確認して完了を表示する。保存後に最後の応答が失われた場合、Windowsは保存済みキーを保持し、通常の認証接続で復帰する。
- 登録通信は非ブロッキングI/Oでキャンセルと期限を確認する。パケット長・試行回数・通信時間に上限を設ける。読み取りを引き延ばす相手も期限で切断する。

参照：[SPAKE2の実装とAPI](https://docs.rs/spake2/0.4.0/spake2/)、[Magic WormholeのPAKEを用いた通信設計](https://magic-wormhole.readthedocs.io/en/latest/client-protocol.html)。本アプリ独自の組み合わせと状態管理について、第三者のセキュリティ監査が済んだという意味ではない。

## 保存と既存設定

MacはKeychainのgeneric passwordを使用。サービス `local.knit.connection`、アカウント `pairing-token-v1`。
WindowsはDPAPIのユーザースコープで保護し、`%LOCALAPPDATA%/Knit/connection.dpapi` へ保存。平文の長期キーを設定ファイルやコマンドラインに書かない。保存時は一時ファイルへの書込み・同期・上書き禁止の移動を行う。

Windowsの接続先ヒントは同じディレクトリの `paired-host.txt`。秘密情報ではなく、常に保存キーによる認証が別途必要。明示的なhost設定を優先し、未指定時にヒントを再接続候補として使う。鍵・接続先ファイルは公開ZIPへ含めない。

既存env設定を優先し、資格情報を上書きしない。旧形式のenvキーは従来どおり使用できるが、6桁登録へ自動変換しない。登録画面を閉じても作成済みのMacの長期キーは保持する。
Windowsの自動起動は `--background` を使い、未登録時に案内を繰り返さない。

保存API：[Apple Keychain](https://developer.apple.com/documentation/security/adding-a-password-to-the-keychain)、[Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/win32/seccrypto/example-c-program-using-cryptprotectdata)。

## 検証

- 正しいコード、誤コード、3回での受付終了、成功後の再利用拒否。
- 不正なパケット長、保存失敗、期限切れ、停止した通信の切断、クライアント/サーバのキャンセル。
- MacとWindows間で、一時キーを使った登録通信を実機検証。通常の資格情報を読み書きしない専用プローブを使用。
- Macの招待画面→Windowsの実際の入力画面→認証→DPAPI保存→Macの完了表示まで実機で検証。保存先は一時ディレクトリに隔離し、復号と接続先の保存を確認して試験後に削除。
- 両OSのネイティブ画面とWindowsの入力エラーを確認。確認モードの探索先・コードはサンプル。
- Keychainの一時項目で保存・読込・重複拒否を検証済み。Windows実機のDPAPI・保護ファイルの保存/読込/改ざん拒否も検証済み。
- `--preview-setup` は保存・通信を行わない。debugビルド専用の `--probe-setup` は実通信の登録試験用。Macは一時キー、Windowsは `KNIT_PROBE_DATA` で指定した隔離保存先を使う。releaseビルドにはこの入口を含めない。

## 残る商品化工程

登録の取消・鍵の失効と再登録、旧形式envからの明示的な移行、署名済み更新時のKeychainアクセス継続、初見ユーザーによる導入試験、権限設定から入力共有までの新規環境での通し試験。稼働アプリの置換やOS権限の実変更は今回の検証に含めない。
