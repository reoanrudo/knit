# 初回登録：自動検出と6桁コード

## 利用者の操作

**6桁を打つ必要はない。** 見つけた相手を「信頼してよいか」を、Macの画面に出る4桁の番号を人が確かめて決める(打たずに、選ぶだけ)。

1. MacでKnitを起動する。初回はすぐに待ち受けの画面が出る(2回目以降は設定「接続」の「端末を登録…」から出す)。
2. WindowsまたはAndroidでKnitを開く。同じWi-Fi・LAN・有線直結にいるMacを自動で見つけ、**1台だけなら自動で確認を求める**(複数なら選ぶ。見つからなければMacのIPv4アドレスを入力する)。
3. Macに4桁の番号と相手の名前・アドレスが出る。**WindowsまたはAndroidには4つの番号の候補が出るので、Macの画面と同じ番号を選ぶ。** 選ぶと、Macでは「許可」を押せる。
4. Macで「許可」を押すと登録が完了し、Macの画面は自動で閉じる。アクセシビリティ権限は、システム設定でKnitをオンにすると自動で次へ進む。以後は保存した接続キーで自動接続する。

心当たりのない要求は、Macで「拒否」を押す(Returnで押される既定のボタンは「拒否」)。WindowsやAndroidで違う番号を選ぶと、依頼は取り消される。確認前に閉じても取り消される。

**Macの画面を見ずに押しても通らない**ようにしてある。Windows・Androidの側は、Macに出ている番号を読まないと正しい候補を選べない
(見ずに選ぶと1/4しか当たらず、外れれば取り消す)。偽のMacがWindowsをだまして接続キーを渡させる、という攻撃を防ぐためで、これが番号を「見せる」だけでなく「選ばせる」理由である。

従来の6桁コードも使える。承認方式が使えない古い版の相手や、自動で見つからない場合のために、Macの画面に「手入力コード」として表示される。Windowsではコード欄に6桁を入れると、6桁そろった時点で自動で登録する。

長いキーの手動受け渡しは不要。IPは接続先を探すための情報であり、接続を許可する接続キーにはしない。
探索が届かないTailscale・AP隔離環境ではIPを使う。同じLANでは次回以降も自動探索し、IP変更に対応する。手動経路のIPが変わった場合は接続設定の更新が必要。

### なぜ確認が要るのか

入力共有は「その機器を操作できる」権限そのものになる。確認なしで自動につなぐと、同じネットワークにいる別の機器が、Macのふりをして
Windowsへ入力を送ったり、Windowsのふりをして、切り替えた時のキー入力(パスワード)を受け取れてしまう。番号の見比べは、
「いま目の前にある2台が互いに話している」ことを、人が確かめる手段になる。

## 承認方式の通信

- 6桁方式と同じ待ち受け(TCP/UDP 24904、登録画面を開いている間だけ、5分・最大3回の試行)を使う。最初の依頼の印(`KNIT-SAS1`)で方式を見分ける。
- 鍵交換は X25519。**依頼側が先に鍵を約束する**(`BLAKE2s(公開鍵 || ノンス)` を送り、Mac の公開鍵を受け取ってから自分の公開鍵とノンスを明かす)。
  これにより、確認番号を都合のよい値に合わせるための鍵の総当たりができない。約束と違う鍵は、利用者への確認を出す前に拒否する。
- 確認番号は、招待IDと両者の公開鍵・ノンスのハッシュ(トランスクリプト)から4桁を取り出したもの。割り込む機器がいれば、両画面の番号が食い違う。
  4桁で足りるのは、約束で総当たりを封じ、かつ試行が3回で締め切られるため(割り込みが成功する確率は1回あたり約1/10000)。
- Macは番号を表示し、依頼側は本物の番号と3つの無関係な番号を並べた**4択**を出す(Macの画面を読まないと選べない)。Macの許可は、その相手が心当たりのある端末かの判断で、
  番号を打つ・見比べる作業とは別に必要。
- 導いた鍵を PSK に、6桁方式と同じ Noise(NNpsk0)で暗号化経路を作り、その中で長期キー(接続キー)を渡す。**Macの許可と依頼側の確認の両方が済むまで、暗号化経路は始まらない**。
  割り込みがあれば両側の鍵が異なり、経路の確立に失敗するため、番号を見誤っても接続キーは渡らない。
- 許可を待つ間は最長120秒。応答が無ければ拒否として扱う。全ての失敗と拒否は試行回数に数え、3回で受付を締め切る。
- 待ち受けを塞ぐ攻撃への対策: 約束の照合が済むまでは通常の短い期限(8秒)のまま。確認待ちの間は依頼側の切断を監視し、去ったら確認画面を取り下げる。
- 表示名は相手が名乗ったもので確かめられていない。制御文字・ゼロ幅・方向マークなど見た目を偽装できる文字は除き、相手のアドレスも併せて表示する。
- **Mac 側のビーコン表示名は固定の匿名ラベル「Knit (Mac)」**。登録待ち受けの応答は
  LAN 上の全機器から見えるため、コンピュータ名(人名・社名を含むことがある)は流さない。
  どの Mac かは4桁の確認番号とアドレスで確かめる(名前は登録の突合に使わない)

### 既知の限界

- **Macの許可は人の判断**: 同じネットワークにいる別の機器が、登録画面が開いている5分の間に、それらしい名前で要求を送れる。Macの確認画面は既定が「拒否」で、
  名前とアドレスを表示するが、見ずに「許可」を押せば通る(攻撃者は切り替えた時のキー入力を受け取る立場になる)。心当たりのない要求は拒否する。
- 4桁の番号による割り込みの成功確率は、1回あたり約1/10000(3回の試行で約3/10000)。
- 実機での通し試験と、第三者による安全性の監査は未実施。
- 依頼側が保存に失敗した場合は、6桁方式と同じく成功を返さない。

## 6桁コードの通信

- Macの登録画面を開いている間だけ、TCP/UDP 24904で待ち受ける。通常の入力通信と分離。
- コードはOS乱数から生成し、5分・最大3接続試行・成功1回で終了。閉じると探索応答と進行中ソケットも停止する。新しく開くとコードも変わる。
- 探索は表示名と送信元アドレスのみ。コード・長期キー(接続キー)・コードのハッシュを公開しない。探索結果そのものは信頼しない。表示名は端末名ではなく匿名ラベル(Knit (Mac) 等)で、コンピュータ名は LAN に公開しない。
- 候補一覧は応答と登録待ち受けポート(TCP 24904)への接続確認だけで載るため、名前はいくらでも偽れる。**心当たりのない候補は選ばない**(本物なら Mac 側にも同じ登録画面が出ている)。
- SPAKE2（`spake2 0.4.0`）で短いコードから共有セッション鍵を導出する。毎回新しい状態を生成し、招待IDと役割を紐付ける。
- 導出した鍵で通常接続と同じNoise方式・ライブラリでハンドシェイクを行い、相互に鍵の一致を確認した暗号化経路で長期キーを渡す。6桁コードを直接NoiseのPSKにしない。
- Windowsは認証済みの鍵をOS保護領域へ保存してから応答する。Macはその応答を確認して完了を表示する。保存後に最後の応答が失われた場合、Windowsは保存済みキーを保持し、通常の認証接続で復帰する。
- 登録通信は非ブロッキングI/Oでキャンセルと期限を確認する。パケット長・試行回数・通信時間に上限を設ける。読み取りを引き延ばす相手も期限で切断する。

参照：[SPAKE2の実装とAPI](https://docs.rs/spake2/0.4.0/spake2/)、[Magic WormholeのPAKEを用いた通信設計](https://magic-wormhole.readthedocs.io/en/latest/client-protocol.html)。本アプリ独自の組み合わせと状態管理について、第三者のセキュリティ監査が済んだという意味ではない。

## 保存と既存設定

MacはKeychainのgeneric passwordを使用。サービス `local.knit.connection`、アカウント `pairing-token-v1`。
WindowsはDPAPIのユーザースコープで保護し、`%LOCALAPPDATA%/Knit/connection.dpapi` へ保存。平文の長期キーを設定ファイルやコマンドラインに書かない。保存時は一時ファイルへの書込み・同期・上書き禁止の移動を行う。

Windowsの接続先ヒントは同じディレクトリの `paired-host.txt`。秘密情報ではなく、常に保存キーによる認証が別途必要。明示的なhost設定を優先し、未指定時にヒントを再接続候補として使う。鍵・接続先ファイルは公開ZIPへ含めない。

既存env設定を優先し、資格情報を上書きしない。旧形式のenvキーは従来どおり使用できるが、6桁登録へ自動変換しない。登録画面を閉じても作成済みのMacの長期キーは保持する。
Windowsの自動起動は `--background` を使い、未登録時に案内を繰り返さない。

保存API：[Apple Keychain](https://developer.apple.com/documentation/security/adding-a-password-to-the-keychain)、[Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/win32/seccrypto/example-c-program-using-cryptprotectdata)。

## 登録の初期化(全端末の締め出し)

登録した端末を後から外したいときは、Mac の設定「接続」の「すべての登録を初期化…」を使う。
確認ダイアログを通すとキーチェーンの接続キーを削除して新しく作り直し、Knit を再起動する。
接続キーは全端末共通の共有鍵のため、**旧いキーを持つ全端末が以後接続できなくなる**(実質の締め出し)。
再び使う端末は「端末を登録…」から再登録する。環境変数 `KNIT_TOKEN` 運用時はキーチェーンを
初期化しても締め出せないため、画面が初期化を中断して案内する。手順の詳細は
[使い方ガイド](usage.md)の「登録の管理」を参照。

## 検証

- 正しいコード、誤コード、3回での受付終了、成功後の再利用拒否。
- 不正なパケット長、保存失敗、期限切れ、停止した通信の切断、クライアント/サーバのキャンセル。
- MacとWindows間で、一時キーを使った登録通信を実機検証。通常の資格情報を読み書きしない専用プローブを使用。
- Macの招待画面→Windowsの実際の入力画面→認証→DPAPI保存→Macの完了表示まで実機で検証。保存先は一時ディレクトリに隔離し、復号と接続先の保存を確認して試験後に削除。
- 両OSのネイティブ画面とWindowsの入力エラーを確認。確認モードの探索先・コードはサンプル。
- Keychainの一時項目で保存・読込・重複拒否を検証済み。Windows実機のDPAPI・保護ファイルの保存/読込/改ざん拒否も検証済み。
- `--preview-setup` は保存・通信を行わない。debugビルド専用の `--probe-setup` は実通信の登録試験用。Macは一時キー、Windowsは `KNIT_PROBE_DATA` で指定した隔離保存先を使う。releaseビルドにはこの入口を含めない。

## 残る商品化工程

端末ごとの個別の登録取消(1台だけの剥奪。現在は「すべての登録を初期化」での全端末締め出しのみ実装)、旧形式envからの明示的な移行、署名済み更新時のKeychainアクセス継続、初見ユーザーによる導入試験、権限設定から入力共有までの新規環境での通し試験。稼働アプリの置換やOS権限の実変更は今回の検証に含めない。
