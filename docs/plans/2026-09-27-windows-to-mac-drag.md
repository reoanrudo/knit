# WindowsからMacへのファイルドラッグ

状態（2026-09-27）：実装・両アプリへの反映・再接続確認まで完了。
Mac・共通の通常テスト59件とWindows実機の7件が成功した。
AppKitの生成試験も成功。Explorer → Finderの実操作は利用者の確認待ち。

## 完了条件

現在の共有マウスでWindowsのExplorerから通常ファイルを掴み、接続辺へ運ぶ。
押したままMacへ移り、Finderのフォルダやファイルを受け取れるアプリへ離してコピーできる。
原本を保持し、取り消し・切断・古い転送結果で別の操作を開始しない。

## 実装

1. Windowsの接続辺に、共有操作中の左ボタン押下時だけOLE受け取り領域を出す。
   `IDropTarget`から`CF_HDROP`を読み、元のドラッグのファイルを取得する。
2. 受け渡しIDを付けたOffer / Accept / Ready / Commit / Cancel / Doneを本線へ追加する。
   ファイル転送にも同じIDを付け、接続経路の順序差で別の操作と混ざらないようにする。
3. Macで全ファイルが揃ったらReadyを返す。Windows側は境界に掴んだままいることを
   再確認して元のOLE操作をコピーとして完了し、Macへ制御を戻す。
4. Macのメインスレッドで`NSDraggingSession`を開始する。受信済みファイルURLと
   OSのファイルアイコンを渡す。終了・取消を両側に伝える。
5. 古い版との接続は維持し、新しい受け渡しに対応する版同士でだけ機能を有効にする。

## 今回の制約

全データを受け取ってから境界を越えるため、大容量ファイルでは境界で転送待ちになる。
通常ファイル・複数選択が対象。フォルダ、仮想ファイル、Windowsに接続した別のマウスを
Macへ共有する機能はこの変更に含めない。未対応形式は受け入れず原本を保持する。
File Promiseによる転送完了前のドロップは、対応アプリの検証を伴う別の拡張とする。

## 検証

- 識別番号、取消、遅延した完了、容量超過、転送中断の回帰テスト。
- Windows実機でデータオブジェクト取得とOLE対象登録を検証。
- MacでNSDraggingSourceとAppKitの引数・セレクタを検証。
- 通常テスト、両OSビルド、実機配備と再接続。
- 最後にExplorer→Finderへの実操作を確認する。OS API単体の検証とは区別する。
