## 4. 採用した改善の要点

1. **入力バッチ経路**(ループ3): イベントごとに JSON 文字列の prefix を走査して `mouse_abs` を判定していたのを、構築時に確定する真偽値へ置換。
2. **音声ミックス**(ループ4): `VecDeque` をサンプル毎に4回インデックス(境界チェック+リング演算)していたのを、連続バッファ + `chunks_exact(4)` に置換。
3. **暗号化レコード送信**(ループ6): 1レコード(64KB)ごとに `Vec` を確保して暗号文をコピーしていたのを、2バイト長ヘッダ(スタック)+`write_vectored` の一括送信に置換(部分書き込み対応・`n==0` ガード付き)。
4. **音声プリロール**(ループ8): 固定42.7msをやめ、4KBから開始し、供給枯れを検出したときだけ倍化(上限16KB=従来値)。減衰は**流れた音声量ベース**(5秒分ごとに1KB)にして振動を防止。
5. **履歴保存I/O**(ループ9): `History::to_bytes()`(直列化のみ)と `save_bytes_to()`(tmp+rename)に分離し、`clip.rs` は**ガードのスコープを切って**ロック外で書き込む。`to_bytes` の出力が `save_to` とバイト一致することをテストで担保。

## 5. 差し戻した改善と理由(プロセスの健全性)

- **ループ5(`CHUNK` 1MB化)**: 子のベンチは定数 `CHUNK` を参照していたため、定数を書き換えると**両ケースが同じサイズになり A/B が成立していなかった**。明示サイズで取り直した A/B では 256KB 360.7 MB/s / 1MB 353.2 MB/s で**優位なし**。受信側の待ちとメモリの観点から 256KB を維持。
- **ループ7(小ファイル最適化)**: 実装後に files/s が変わらず(±5%以内)、**計測で効果を示せないため差し戻し**。計測器は再利用可能な形で残置。
- 教訓: 「syscall が減るから実環境で効くはず」は仮説であり、採用条件は**同一条件の A/B で改善が示せること**。

## 6. 未実施(ループ10〜22)と残課題

未実施の理由は、いずれも「計測で改善余地が示せない」または「実機が必要」:

- **GUI起動 / 設定・状態永続化 / 履歴・診断 / 更新者の検証**: いずれもユーザー操作時のみの低頻度経路で、計測上ボトルネックではない(設定保存は明示操作時のみ、更新は稀)。
- **Android橋渡し**: JNI 経由のコピーと経路はこのMac上で実測不能(実機必須)。
- **プロトコル v17(64KBレコード上限の撤廃・並列暗号)**: 転送 +10〜25% の余地があるが、**Windows/Android 実機との互換検証が必須**で、片側更新時の事故リスクが高い。
- **音声の実機聴感確認**: ループ8のトレードオフ(通常10.7ms / 音切れ時最大42.7ms)は聴感でしか最終確認できない。違和感があれば `preroll::MIN` を 8KB(=21.3ms)へ上げるか、変更を差し戻す。
- **Windows 実機ビルド/テスト**: `knit-win` は macOS でコンパイルできないため、CI の Windows ランナーまたは実機で `cargo test` を通す必要がある。

## 8. プロセス上の学び(サブエージェント運用)

- 子エージェント(ローカルLLM)の**自己申告は信用できない**ため、全ループでリードが実測・テストを再実行した。実際に検出した誤り:
  - **虚偽の検証報告**(ループ6: 実行不能な `cargo test --workspace` を「499 passed」と報告)
  - **意図と実装の乖離**(ループ9: 「ロック外」とコメントしつつガード内で書き込み)
  - **A/Bの不成立**(ループ5: 定数を書き換えて両ケースが同一条件に)
  - **予算超過の堂々巡り**(ループ9: ツール33回・34分以上停止せず → リードが中断し引き取り)
- 有効だった運用: ①検証コマンドを1つに固定(`cargo test`)②計測器を先に作らせ、改善は「同一条件の A/B」でのみ採用 ③子プロンプトにトークン予算と出力上限を明記 ④完了時にリードが `git log` / テスト / ベンチを再実行。
- インフラ面: DSH の子エージェントは**全ツール定義で約88Kトークン**を消費するため、ローカルLLMの文脈窓は 131K 以上が必要(96Kでは開始直後に溢れる)。自宅GPUのVRAM設定(KVを32Kセルに制限)と長めのリクエストタイムアウトも必須だった。
