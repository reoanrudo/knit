# Knit ドラッグ&ドロップ 実機確認ランナップ(2026-10-18)

この文書は、**コードでは検証できない部分**(実機の対話操作・見た目)を、あなたが短時間で
確かめるための手順書です。各手順は「何をするか → 期待する結果 → 違ったときに集める情報」の形です。
所要は全部で20〜30分を見込んでいます。

## 0. 準備

| 側 | 必要なもの |
|---|---|
| Mac | このリポジトリのビルド(`cargo build --release -p knit-mac`)または配布物 |
| Windows | **遅延提供を試す場合のみ**このリポジトリのビルド(`cargo build --release -p knit-win`) |
| 両方 | 同じネットワークで接続できること(Tailscale 可) |

ログの場所:
- Mac: `~/Library/Logs/knit/knit-mac.log`(5MB でローテーション)
- Windows: コンソール出力(トレイ常駐なら起動したターミナル)、またはトレイの「診断」

まず **両方を通常どおり起動**して接続してください(`KNIT_LAZY` は付けません)。

## 1. ドラッグの反復(最優先・5分)

**なぜ**: 「モード切替後に一度クリックすると、以後のドラッグが全部“保存のみ”に化ける」バグを
修正しました(`c49f95d`)。これが直っているかの確認です。

1. Mac から Windows の画面へカーソルを移し、**Windows 側で2〜3回クリック**する(この操作が以前は
   バグを誘発していました)。
2. Finder で小さめのファイルを1つ掴み、**Windows のデスクトップ(またはフォルダ)の上で離す**。
3. 期待: そのファイルが**離した場所に現れる**。
4. **2〜3回繰り返す**(毎回、間に Windows 側でクリックを挟む)。
5. 期待: **毎回**置ける。

**違ったとき**(置けずに `Downloads\Knit` に入ってしまう等)に集める情報:
- Mac のログ: `[drag] mac->win offer`、`[file] 掴みドラッグ切替`、`[drag] mac->win … 転送完了`
- Windows のログ: `[drag] DoDragDrop 開始`、`[drag] ドロップ完了` または
  `[drag] 受信のみ扱い(クリップボードは変えません)`

## 2. カーソル近傍の案内(HUD)(10分)

**なぜ**: 断った理由がカーソル付近に出るようにしました(I3)。**私には画面が見えず、
2行で正しく描画されるか・クリックを邪魔しないかを確認できません**(検証役の実機プローブで
API の実在は確認済みですが、見た目は未確認です)。

1. Finder で**65件以上**のファイルを選び、端へ掴んで持っていく。
   - 期待: カーソル近傍に「**掴みすぎです(64 件まで)**」+「このまま離すと Mac 内の操作になります」の2行。
   - 確認すること: **2行で読めるか**(切れていないか)/ 1.6秒ほどで消えるか / **そのまま離しても
     Mac 内で普通にドロップできるか**(クリック透過が効いているか)。
2. 相手(Knit)を終了した状態で、同じくファイルを掴んで端へ持っていく。
   - 期待: 「**転送の準備中です(少し待って掴み直す)**」。
3. 期待どおりでない場合: 出ない/文字が切れる/クリックを奪われる/消えない などを教えてください
   (位置は `crates/common/src/hud.rs` の `place()`、文言は `Refusal::hud_line()`)。

## 4. 失敗からの回復(5分)

1. Windows 側の Knit を終了する(または回線を切る)。
2. Mac でファイルを掴んで端へ → 「転送の準備中…」で越えられない。
3. メニューバーを開く。
   - 期待: 「**直前: 渡せませんでした(…)**」の行と、必要なら「**もう一度送る**」。
4. Windows 側を復帰させ、**「もう一度送る」**を押す。
   - 期待: そのファイルが送られ、成功したら**「直前:」の行と「もう一度送る」が消える**。
5. あわせて「**受信フォルダを開く**」(常設)も試してください(Mac 側の受信フォルダが開きます)。

## 5. 遅延提供(押し続け不要)の実機確認 — 上級・15分

**なぜ**: 1GB=34秒/10GB=5分41秒 のあいだ物理ボタンを押し続ける問題への答えです。**実装は
できていますが、Explorer が遅延提供を受けて実際にコピーできるかは実機でしか確かめられません。**

### 準備(Windows 側)
```
cd <knit のフォルダ>
cargo build --release -p knit-win
set KNIT_LAZY=1
target\release\knit-win.exe
```
※ 既定は無効です。**`KNIT_LAZY` を付けなければ従来方式**のままです(逃げ道)。

### 手順
1. Mac と接続する(バージョンが両側 17 であること。Mac を先に新ビルドへ)。
2. Mac のログに `[drag] mac->win manifest <id>: N 件(遅延提供)` が出ることを確認。
3. **大きめ**(数百MB〜数GB)のファイルを掴んで Windows のデスクトップへ運ぶ。
   - 期待: **到着を待たずに**ドラッグが始まり(Windows のログに
     `[drag] 遅延提供で DoDragDrop 開始`)、**離した瞬間にコピーが始まる**。
   - Explorer のコピー進行が「データが届いた分から」進む。
   - Windows のログに `[drag] 遅延提供: 受理を返しました(id …)`。
   - 完了時: `[drag] 遅延提供のドラッグ終了: effect=1 (置けた)`。
   - Mac の通知: 「**…の画面に置きました(ドロップできました)**」(= 相手が確認した事実)。
4. **途中で離す**(転送が終わる前に離す)を試す。
   - 期待: そのまま置けている(押し続け不要の本命)。
5. 失敗させる: 転送中に接続を切る。
   - 期待: 30秒で `IStream::Read` が諦め、Explorer 側にエラーが出る(**部分ファイルが
     置き場所に残らないこと**を確認)。Mac の通知は「保存のみ」または失敗の理由。
6. **やめたいとき**: `KNIT_LAZY` を外して Windows を再起動 → 従来方式に戻ります。

**違ったとき**に集める情報(これがあると原因を追えます):
- Windows: `[drag] 遅延提供…` の行すべて / Explorer のエラー全文 / 置き場所に残ったファイル
- Mac: `[drag] mac->win manifest …` / `[drag] mac->win … 転送完了` / 通知の文言

### 既知の制限(実装済みだが未確認の点)
- `IDataObjectAsyncCapability` は実装していません(Explorer が同期で読む想定)。非同期を要求する
  受け手では挙動が変わる可能性があります。
- 速い転送(小さいファイル)では、受理の往復より送信完了が先に来る場合があり、そのときは
  事実(「置きました」)ではなく慎重な本文(「転送完了。相手側で受け取れます」)になります。
  誤った言い切りはしません。
