実装・コード変更は行いません。判定資料を作って私に返すまでが仕事です。
返答は日本語のです・ます調で。コミットは私が指示した時だけ行ってください。

## 決まっていること(利用者の決定。覆さない)
- 本質: 「異なる OS の機器の間を、入力と持ち物(コピーしたもの・ファイル)が、毎日確実に、
  何も考えずに行き来できること」
- 判定は essence-review の5つの問いで行う: ①境界が原因か ②毎日起きるか ③代わりがあるか
  ④信頼を削らないか ⑤境界を意識させないか
- 当面、新機能は足さない。時間は品質・導入・更新に6割(ロードマップ §5)
- タブレットを PC の追加画面・ペンタブにする方向と、横断検索(Search My Desk)は復活させない。
  横断検索は撤去済みの前例があり、同じ基準で既存機能を切ることにためらいはない
- この監査は判定案の提出まで。実際の削除・コード変更は私の判断のあとで行う

## ユーザー目線の支柱(全機能の判定で必ず通す)
- 利用者像: Mac と Windows を毎日並べて使う開発者・クリエイター。ただし開発者向けの操作
  (env 編集・adb・ターミナル)は普通はしない
- 各機能を3つの場面で問う:
  1. 最初の5分: 案内なしで自然に使えるか。説明が要る機能か
  2. 毎日の机: 導入1週間後に本当に使っているか。vision §2 の摩擦を1つ消しているか
  3. 無くなった時: 消えたら何で困るか。OS 標準・一度の設定・既存アプリで代えられないか
- 「動く・便利そう・技術的に面白い」は存続理由にしない。「境界を1回消しているか」だけが理由

## 監査対象(棚卸しの起点。ここに無い機能も見つければ追加する)
- Input 層: 画面端切替(edge/hotkey の両モード・fast edge・境界回数/滞在/四隅の調整)・
  修飾キーとショートカット翻訳・かな/英数キーと IME 引継ぎ・右⌘=右Ctrl・
  音量/メディアキー転送・F1〜F6 のけ直し(実験的)
- Object 層: クリップボード同期(テキスト/画像/ファイル)・掴みドラッグの境界越え・
  クリップボード履歴(上限50件・画像60件)・smartguard(ollaya による機密検査・実験的)
- Context 層: Continue Here(⌥⌘T)・App Handoff(KNIT_APP_HANDOFF・既定 OFF)・
  Throw(⌥Enter で投げる)・RunApp/アプリ一覧(横断検索の残骸か現役か、コードで実態確認)
- 机と接続: 音声集約と自動ミュート・音声ミックス・画面ロック連動・複数台同時接続と切替・
  モニター構成の自動交換・ターミナル Control(KNIT_CTRL_APPS)・ゲームモード・
  DERP 中継の通知・有線直結の案内
- タブレット: adb 精密モード(開発者向け)・Mac のトラックパッド→タブレット(ピンチ等)・
  標準モード(開発中・docs/android-app-vision.md)
- 設定: 設定ウィンドウの項目と env 変数(docs/usage.md に41行以上。利用者が触るべきでないもの)
※desksearch.rs(横断検索)は撤去済み。履歴メニューや検索窓の現存実態はコードで確認してから判定する

## 進め方
1. 機能棚卸し: usage.md・CHANGELOG・コードで、各機能の実態・既定値・使われ方を確認する。
   特に「誰も既定から変えずに使う」機能と「既定 OFF のまま誰も有効にしない」機能を洗う
2. 各機能を5つの問いとユーザー目線3場面で判定し、次の4分類へ割り当てる:
   - 維持(コア): 境界を消す本体。品質投資の対象
   - 実験的のまま: 機能は残すが既定 OFF・非公開にする(env gated のみ)
   - 隠す: 動作は残すが設定 UI・ドキュメントに出すのをやめる
   - 削除候補: コード・プロトコル・ドキュメントから外す
3. 「削除候補」と「隠す」は、依存(呼び出し元・テスト・Msg・ドキュメントの記述)を調べ、
   外す規模(S/M/L)とリスク(プロトコル互換・既存ユーザーへの影響)を付ける
4. 設定項目は「利用者が触るべきもの」だけを画面に出す案にする(env 変数の整理方針を提示)
5. 判定表を docs/reviews/2026-09-30-feature-audit.md に書く。各判定に1行の理由と根拠
   (コードの場所か文書の節)を付ける。essence-review で「残す」判定済みの音声集約・ロック連動を
   覆すときは、新しい根拠を必ず示す
6. 最後に「私が決めるべき論点」(判定が割れるもの・削除すると後戻りできないもの)を5つまで
   列挙して報告する

## 守ること
- コード変更・ファイル削除をしない(作るのは docs/reviews/ の監査資料のみ)
- 実機試験をしない。ビルドしない。タブレット・Windows 機に触れない
- 私の Knit を再起動・再インストールしない
- 公開・外部送信をしない
- 判定は案。最終決定と削除の実施は私が行う
