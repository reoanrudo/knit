# 端末モデル(端末別資格・失効)の実機確認手順(2台)

確認時間の目安: 15分。前提: Mac と Windows の両方を main(または同じ PR ブランチ)の
ビルドへ更新。旧版のままでは登録の意味が変わるため、必ず両方そろえる。

## 1. 登録と一覧(5分)

1. Mac のメニューバーから「端末を登録…」で6桁コードを出し、Windows で参加する
2. Mac のメニューバーに「登録済みの端末(1台)」が出ることを確認する
3. 中を開き、行が `端末名(略号) を失効…` の形で1件あること、先頭に
   「旧形式(共通キー)での接続: 受け付けています」があることを確認する
4. ターミナルで `knit-mac --registry list`(アプリ本体は起動したままでよい)。
   1台載っていて、略号がメニューの行と一致することを確認する

**違ったとき**: メニューに「登録済みの端末」自体が出ない → 台帳が開けていない
(ログの `[registry]` 行)。行は出るが0台 → `--registry list` と
`~/Library/Application Support/Knit/devices.json` を見る。

## 2. 失効(5分)

1. メニューの行をクリックし、確認ダイアログで「失効させる」を選ぶ
2. Windows 側で本線・ファイル送信を試す。接続が切られ、以後の再接続が拒否される
   (Windows 側の状態表示が「未接続(再試行中)」のままになる)
3. Mac のメニューの一覧からその行が消えていること、`--registry list` でも
   0台になっていることを確認する
4. Windows を再起動しても繋がらないことを確認する(トークンが違うため)

**違ったとき**: Windows が繋がったまま → セッションの切断が走っていない。
ログの `[conn] 失効済みの端末` / `[registry] 端末を失効しました` を確認。
`--registry revoke <key_id>` を本体起動中に実行した場合も、最大1秒で切断される
(keepalive の監視)。

## 3. 旧形式の受付を閉じる(3分)

1. メニューの「旧形式(共通キー)での接続: 受け付けています」をクリックし、
   「拒否する」を選ぶ
2. 表示が「拒否中」に変わることを確認する
3. 旧トークンしか持たない端末(この PR より前に登録した端末)は繋がらない。
   その端末を再登録すると、端末別トークンで繋がり、以後は個別失効できる

注意: この操作は取り消せない。戻すには「すべての登録を初期化」で全端末を
再登録する(設定「その他」)。

## 4. 期限切れ(操作権)の確認(2分)

1. Windows で操作中(WIN_MODE)に、Windows 側のネットワークを切る
2. 5秒ほどでカーソルが Mac へ戻る(本線の切断検知15秒より先)
3. 相手の押下は、Leave/切断経路で解放される(Windows 復帰後に入力が張り付かない)

**違ったとき**: 戻らない → ログの `[conn] 操作権の期限切れ`。この監視は
writer スレッドの1秒周期なので、Mac がサーバ役でもクライアント役でも動く
(実際の発火は5〜6秒)。

## 5. 片側だけ戻す場合の注意

Mac だけ旧版へ戻すと、端末別トークンで登録した Windows は繋がらない
(旧版の待受は共通キーのみ)。両側を同じ版へ戻すか、Windows を再登録する。
