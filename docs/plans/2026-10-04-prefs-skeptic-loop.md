# 設定GUI 懐疑(疑いの目)×修正 20周ループ(2026-10-04 実行済み)

## 目的

設定画面のGUIを「人間が扱いやすいか」を反感・疑いの目で持つシニアが観点を変えて
20回レビューし、浮き出た指摘を別のシニア(修正担当)が全件対処する交互ループ。
前々回「探検者10領域」・前回「Deskflow設定UI参照」に続く第4弾で、
**参照物を使わず自製品そのものの UI を疑い倒す**タイプのループ。

## 実行方法(ZCode)

1. 共通参照ドキュメント(/tmp/knit-prefs-skeptic-ref.md)を事前作成し、
   各レビューエージェントに最初に Read させる(対象ファイル・思想・検証コマンド)
2. 各周を直列に実行(後の周が前の実装後のコードを見る):
   - レビュー: `Agent(subagent_type: read-only-reviewer)` で観点を1つ与え指摘最大5件
     「file:行 + 何が人間に辛いか + 最小修正案」形式・推測での指摘は禁止
   - 修正: `Agent(subagent_type: builder)` に報告を貼り全件対処
     検証: `cargo check/test --workspace --exclude knit-win`・`cargo build -p knit-mac`
     ・`--preview-ui [--allow-multiple]` スモーク・コミット禁止
3. 毎周のプロンプトに「直近の周の変更の副作用も疑う」を含め、直しの直しを見せる

- テスト: 開始時388件 → 終了時437件(全緑・+49は幅/文言/組立の保護テスト)
- 主な実装(抜粋):

    (読み込み前の1世代自動バックアップ付き)・Win側履歴消し

    PeerSidesFile)で欄の近くへ保持・通知だけで消えない導線
  - 状態行の整合: 未登録時の嘘案内修正(paired_registered)・再試行/見つからない
    の優先度統一・メニュー開示中の書き換え抑制(状態行・3ポップアップ)
  - 復活した消えた機能: カーソル速度スライダ・スクロール互換チェック

## 運用の注意

- 「疑いの目」レビューは観点を1つに絞ると指摘が深くなる(1周5件×20周が上限の目安)
- 修正担当には必ず「直近の変更の副作用も疑う」レビューを次周で回す:
  このループの指摘の約3割は前周修正の副作用だった
- 幅チェックは文言関数の純粋関数化+px上限テストが有効(全角11-13px/ASCII6-7px換算)
- 実機確認が残る物: メニュー開閉の脈動停止・2台同時登録・ADB送信中表示・
  ページ最下部2行目の見え方・⌘W/Enter/Esc の実キー操作
