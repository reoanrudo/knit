# 接続安定性・設定UIの改善（2026-09-30）

MacとWindowsを毎日併用する個人向けに、接続の維持と設定の分かりやすさを優先した。
既存の作業中の変更を維持し、今回の実装はMac側の接続管理・送信キュー・受信ドラッグ・設定UIに絞った。

## コードで確認した問題と修正

| 問題 | 修正後の挙動 |
|---|---|
| 待機端末の切断で、操作中の端末まで切断処理された | 端末IDと接続世代が一致する端末だけを外し、操作中の場合だけ共通の切断処理を行う |
| 操作中の端末を一覧から外した後、旧送信口を別の端末へ戻し得た | 操作中の所有者を無効化して旧送信口を閉じ、残りの端末をIDで選ぶ |
| 新規・待機端末の再接続が操作する端末の選択を奪った | 初回接続と操作中の同一端末の再接続だけ自動選択する |
| IDから添字を求めた後に一覧が変わると別端末を選び得た | UIの選択をIDで受け取り、一覧の変更と選択を直列化する |
| 送信キューが接続を区別せず、切替前後の入力を束ねた | 接続世代が違う行を束ねず、書き込み時にも古い世代を破棄する |
| 古い受信セッションが選択中の状態を変更し得た | 受信処理でもIDと接続世代を確認する |
| ドラッグ切断時に受信スレッドからAppKitを操作した | 表示の後処理をmainスレッドに渡し、遅い終了通知をsource単位で照合する |
| 設定の操作ボタンのアクションが登録されていなかった | 専用アクションを登録し、接続済みの場合だけ操作へ進む |
| 設定の画面位置変更が選択中の端末に反映されなかった | 選択中の端末の位置・保存値・相手へ送る設定を更新する |

送信先切替では、旧端末にLeaveを直接送ってキー・ボタンの解放を依頼してから送信口を待機へ戻す。
画面端でファイルを持ったまま切り替える経路も、送信先を確定してからドラッグの予告を送る順序にした。
通信メッセージの形式・プロトコル版は変更していない。

## 設定画面の改善

- 接続ページに端末の選択を追加。未接続時は「接続を待っています」を表示する。
- 操作・Macへの復帰・ファイル送信・音量ボタンの有効状態を接続と操作状態に合わせる。
- 画面端で1回・2回・待つ・ショートカットのみの各方式に合った案内を表示する。
- カーソル速度・待ち時間・2回触れる間隔に現在値を表示する。
- 待ち時間と2回触れる間隔は、その方式を選んだときだけ調整できる。
- 接続先に応じた名称とAndroidの状態・機能制約を表示する。
- サイドバーの選択色はmacOSのアクセントカラーを使う。長いラベルには省略表示とツールチップを付ける。

| 検証 | 結果 |
|---|---|

| 内訳 | common 62件、ドラッグ統合5件、Mac 53件 |
| 今回追加した回帰テスト | 9件。端末の登録・切断5件、送信キュー3件、ドラッグ後処理1件 |
| `cargo build --locked -p knit-mac --release` | 成功 |

設定プレビューでは、端末の選択・操作・ファイル送信・音量ボタンの無効状態、
待つ方式で待ち時間だけ有効になること、ショートカット方式で両方の時間調整が無効になることを確認した。
待ち時間を650ms、カーソル速度を1.5倍へ変更すると表示値が追従し、配置を右から左へ変更すると図が追従した。
プレビューは入力・通信・音声を動かさず、設定も保存しない。

## 残る検証・対象外

実行中の常用版の差し替えとWindowsへの配布は行っていない。
Windowsとの実機往復、スリープ復帰、複数端末の同時切断、実際のファイルドラッグ、音声再生は追加の受け入れ試験が必要。
AppKitが終了通知を返さないドラッグでは、解放を急がずsourceを保持する。実機で通知と解放を観察する必要がある。
また、送信口の切替と待機端末の生存確認には既存の同期書き込みが残るため、ネットワーク停滞時の入力応答性は引き続き改善対象となる。
英語UI・Windows側の設定UI刷新・配布の公証・課金導入は今回の範囲に含まない。
